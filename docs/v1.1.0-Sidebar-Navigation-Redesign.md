# v1.1.0 — Sidebar Navigation Redesign

Frontend-only minor release on top of the frozen `v1.0.0` baseline (see
`docs/Version-1-Freeze-Declaration.md`), tagged separately per the
project owner's own explicit direction. `v1.0.0` itself is untouched.

## Objective

The pre-redesign sidebar (`lib/nav-items.ts`'s `NAV_ITEMS`/`LEARN_NAV_ITEMS`,
rendered by `components/layout/AppLayout.tsx`) was one continuous,
82-item column with no grouping, no collapse, no compact mode, and no
pinning. This release restructures it into 10 named, collapsible groups
with active-route highlighting, a compact icon-only mode, a "Frequently
Used" pinned strip, and persisted user preferences — without removing or
relocating any existing route.

## Audit performed before implementation

- **Canonical navigation source**: `artifacts/ravish-trading/src/lib/nav-items.ts`
  — a flat `NAV_ITEMS: NavItem[]` (68 items) + `LEARN_NAV_ITEMS: NavItem[]`
  (9 items) = 82 total, already the single source both `AppLayout.tsx` and
  `components/command/CommandPalette.tsx` read from (Phase 10's own
  "unify, don't duplicate" precedent).
- **Route/permission rules**: every route is wired in `App.tsx` via
  `wouter`'s `<Route>`; none carry a route-level permission guard today
  (the platform's own tenant-isolation model scopes data server-side, per
  request, not per-route on the client) — nothing to preserve there beyond
  the routes themselves, which are entirely untouched by this release.
- **Duplicate display links**: the original 82-item flat list had zero
  duplicate `href`s. The redesign's own source specification requested a
  handful of routes (Institutional Mentor, Decision Engine, Institutional
  AI Coach, Trading AI Coach, AI Portfolio Analyst, Value Investing
  School) in more than one of its 10 proposed groups — each was resolved
  to a single canonical group per that same spec's own "prefer a single
  canonical location" instruction; see the table below.
- **Routes not named in the redesign spec**: 3 (`/backtest`, `/scoring`,
  `/journal` — the original, foundational Options Engine's own Backtest/
  Leaderboard/Journal pages, distinct from their newer `/options-backtest`,
  `/trading-journal`, and `/trade-journal-ai` counterparts). Per "do not
  remove any existing routes or functionality," all three were kept,
  placed in the Options Trading group alongside the rest of that original
  flow.

## Behavior implemented

- **Collapsible groups** — `components/ui/collapsible.tsx`, a thin
  wrapper over the already-installed `@radix-ui/react-collapsible` (no
  new dependency). Radix owns `aria-expanded`/`data-state` on the trigger
  natively; a smooth height animation was added via two small keyframes
  in `index.css` (`collapsible-down`/`collapsible-up`), the documented
  Radix pattern using `--radix-collapsible-content-height`.
- **Active-route highlighting + auto-expand** — `SidebarNav.tsx` computes,
  per group, `open = containsActiveRoute || (explicitlySetByUser ? saved
  : group.defaultExpanded)`. A group containing the current page's route
  always renders open, without overwriting whatever the user explicitly
  saved for it — navigating away restores that saved state.
- **"Keep the active link visible"** — a `useEffect` keyed on the current
  route scrolls `[data-active="true"]` into view (`block: "nearest"`)
  after each navigation.
- **Compact (icon-only) mode** — reuses `components/ui/sidebar.tsx`'s own
  existing, previously-unused `collapsible="icon"` support: `SidebarProvider`
  is now driven by a controlled `open={!compact}` prop backed by the new
  persisted `compact` preference (previously the provider ran uncontrolled
  in `offcanvas` mode). `SidebarMenuButton`'s existing `tooltip` prop
  (already built to show only when collapsed + non-mobile) is wired to
  show each item's title in compact mode. Group headers are not rendered
  at all while compact — with labels hidden by the primitive's own
  existing icon-mode CSS, a chevron-only header would be meaningless — so
  every group's icons simply stack in one continuous column, per-group
  collapse state being irrelevant in that mode.
- **"Frequently Used" pinned routes** — up to 6 (`MAX_PINNED`), stored as
  an ordered `pinnedHrefs: string[]`. Every item row gets a hover-revealed
  pin/unpin `SidebarMenuAction` (an existing primitive component, not
  hand-rolled); the pinned strip itself has its own move-up/move-down/
  remove controls. Suggested defaults (Command Center, Options Dashboard,
  Scanner, Portfolio Dashboard, AI Assistant, Settings) already fill the
  6-slot cap, matching the redesign spec's own numbers — a fresh user
  must unpin one default before pinning something new, a real, disclosed
  consequence of "6 suggested defaults" + "up to 6 total" being the same
  number, not a bug.
- **Search** — the existing global "Search or jump to…" Command Palette
  (⌘K/Ctrl+K) is unchanged and untouched; it already reads the same
  flattened `ALL_NAV_ITEMS` list this redesign produces, so it continues
  to find every route regardless of which group is currently collapsed.
- **Persistence** — a single localStorage key, `dk-sidebar-navigation-state`
  (the exact suggested key), holding `{ expandedGroups, compact,
  pinnedHrefs }`. Reads/writes are wrapped defensively (`lib/sidebar-preferences.ts`)
  so private browsing or a quota error degrades to sensible in-memory
  defaults rather than throwing — this platform has no server-side UI-
  preference store to use instead.
- **Responsive behavior**:
  - *Desktop*: full collapsible sidebar + compact-mode toggle
    (`SidebarTrigger`, in the always-rendered main-content header — see
    the fixed bug below).
  - *Tablet* (768–1023px): a first-time visitor (no saved preference yet)
    defaults to compact mode — "a narrower sidebar" — via a one-time
    viewport check in `defaultCompactForViewport()`; a returning user's
    own explicit choice always wins regardless of viewport.
  - *Mobile* (<768px): unchanged from the pre-redesign behavior —
    `components/ui/sidebar.tsx`'s own existing `isMobile` branch renders
    the whole sidebar as a Sheet/drawer. New this release: selecting any
    route now calls `setOpenMobile(false)`, closing the drawer (it
    previously stayed open across navigation); category expansion state
    and the global search trigger are both unaffected by the drawer's
    open/closed state, since neither lives inside the Sheet's own subtree.
- **Accessibility**: Radix's own native `aria-expanded`/keyboard handling
  for group triggers (Enter/Space, native `<button>` semantics — no custom
  key handling written); pinned/unpinned item labels remain in the
  accessibility tree even in compact mode (visually clipped via
  `overflow-hidden`, not `display:none`), so a screen-reader user always
  gets the label while a sighted user sees the tooltip.

## One real bug found and fixed during implementation

The compact-mode toggle button (a `SidebarTrigger`) was first placed
inside `SidebarHeader`, itself a child of `<Sidebar>`. On mobile,
`<Sidebar>`'s entire subtree only renders once its own Sheet is already
open (`components/ui/sidebar.tsx`'s existing `isMobile` branch) — meaning
the very button meant to *open* the mobile drawer was unreachable until
the drawer was already open, an unusable dead end caught by
`AppLayout.mobile.test.tsx`'s own first test. Fixed by moving the trigger
to the main-content header (always rendered, outside `<Sidebar>`) — the
same placement the reference shadcn sidebar pattern itself uses, and
which correctly doubles as both the mobile-drawer opener and the desktop
compact-mode toggle.

## Files changed

- `lib/nav-items.ts` — rewritten: `NavigationItem`/`NavigationGroup`
  types, `NAV_GROUPS` (the new single canonical structure), `ALL_NAV_ITEMS`
  (a flattened derived view, unchanged shape for `CommandPalette`'s sake),
  `DEFAULT_PINNED_HREFS`, `findNavItem`, `findGroupIdForHref`.
- `lib/sidebar-preferences.ts` (new) — persistence types + safe
  load/save + viewport-aware defaults.
- `hooks/use-sidebar-preferences.ts` (new) — the React state wrapper;
  owned once by `AppLayout` and passed down to `SidebarNav` as a prop
  (two independent hook instances would desync).
- `components/ui/collapsible.tsx` (new) — shadcn-style wrapper over
  `@radix-ui/react-collapsible`.
- `components/layout/SidebarNav.tsx` (new) — the grouped/collapsible/
  compact/pinned sidebar content, extracted out of `AppLayout.tsx`.
- `components/layout/AppLayout.tsx` — now renders `<Sidebar collapsible="icon">`
  + `SidebarHeader`/`SidebarNav`/`SidebarFooter`, a controlled
  `SidebarProvider`, and the relocated `SidebarTrigger`.
- `index.css` — 2 keyframes + 2 utility classes for the collapse
  animation (additive only).
- Tests: `lib/nav-items.test.ts`, `lib/sidebar-preferences.test.ts`
  (new), `components/layout/AppLayout.test.tsx` (extended, 1 pre-existing
  assertion updated for the intentional Command Center dual-listing),
  `components/layout/AppLayout.mobile.test.tsx` (new).

No backend file, database migration, API route, or protected file
(`execution.ts`/`optionsMath.ts`/`risk.ts`/`autoExecution.ts`/
`autoAdjustment.ts`/broker integrations) was touched — confirmed via
`git diff --stat` showing this release's entire footprint is inside
`artifacts/ravish-trading/src/` plus this documentation.

## Known limitation carried forward, now larger

The frontend main bundle's shared vendor chunk (already over Vite's
500 kB advisory threshold and disclosed since Phase 9/`docs/Known-Limitations.md`
§6) grew from 460.62 kB to 571.15 kB, since `AppLayout` — and everything
this redesign added to it — is eagerly loaded on every page, not
lazy-split. Same disclosed category, larger number; no new category of
issue. A future manual-chunking pass (already an open, disclosed item)
would need to account for this.
