# v1.5.0, Sprint 20 — Institutional Market Intelligence Engine

## Non-negotiable statement

This is **not** another Research module and **not** another dashboard.
Research remains user-created. Market Intelligence is external
context — continuously gathered, classified, and prioritised, and
connected outward into every existing workflow (Command Centre, Research,
Decision Workflow, Portfolio Intelligence, Knowledge Graph, AI Coach)
rather than duplicating any of them. It never issues a trading signal, a
buy/sell recommendation, an AI price prediction, a second news system, a
second watchlist system, or a broker integration.

| Command Centre | `pages/InstitutionalCommandCentre.tsx` | New `MarketIntelligenceCard`, mirroring `PlaybooksCard`/`DecisionQualityCard`'s exact established pattern (Sprints 18/19). **Conclusion: zero new market-data sources, zero new scoring formulas.**
Every intelligence item is a direct, honest read of an already-existing,
already-tested engine. The only genuinely new logic this sprint is the
classification/composition layer stitching those reads into one feed, and
the per-user entity-linking layer connecting that feed to a user's own
graph/watchlists.

## 2. Architecture — two layers, split by statefulness

### 2.1 Backend: `lib/marketIntelligence.ts` (api-server) — stateless, market-wide

`buildMarketIntelligenceFeed(now, symbols, horizonDays)` composes:

- `eventItem()` — one item per `getUpcomingEvents()` result, categorised by
  `EventRiskEvent.type` (`fomc` → `central_banks`, `earnings` → `earnings`,
  `dividend` → `corporate_actions`, else → `economic_events`).
- `briefingItems()` — 3 items (macro/volatility/market_breadth) from
  `buildMarketBriefing()`.
- `investingMacroItem()` — 1 further, genuinely separate macro item from
  `buildMacroContext()`.
- `optionsActivityItems()` — items for universe symbols whose open interest
  is in the top third AND whose IV rank ≥ 60 (`OPTIONS_ACTIVITY_IV_RANK_THRESHOLD`).

Every item is shaped as a `MarketIntelligenceItem`:

```ts
interface MarketIntelligenceItem {
  id, headline, category, source, dataSource: "SIMULATED" | "LIVE",
  timestamp, impact: "low" | "medium" | "high",
  affectedAssets: string[], affectedSectors: string[],
  potentialRisks: string[], potentialOpportunities: string[],
  summary,
  learnMore: { pathKey, topicKey, label } | null,
}
```

`GET /market-intelligence` (`routes/marketIntelligence.ts`) is a thin,
market-wide (not per-user) pass-through — no auth/tenant scoping needed,
mirroring `routes/events.ts`'s own established precedent, since this is
read-only market analysis, not a per-user resource.

### 2.2 Frontend: `lib/marketIntelligence.ts` + `lib/useMarketIntelligence.ts` — per-user entity linking

`enrichMarketIntelligenceItem()` (pure) computes, per item:

- `isWatched` — an affected asset is on a watched list, **or** the item is
  market-wide (`macro`/`central_banks`) — a disclosed exception, since a
  macro/rate read genuinely affects every portfolio regardless of what's
  on a watchlist.
- `relatedHoldings` — the real intersection of `affectedAssets` and the
  caller-supplied held-symbols set — never fabricated.
- `isPriority` — `impact === "high"` **AND** (`isWatched` OR held) — a
  boolean AND of two already-known facts, never a new importance score.
- `relatedResearch`/`relatedStrategies`/`relatedLessons` — walked directly
  off the Knowledge Graph's own `company:{SYMBOL}` node.
- `relatedPlaybook` — looked up via the static `CATEGORY_PLAYBOOK` map.

`useMarketIntelligence()` (the orchestration hook) composes
`useGetMarketIntelligence()` with both watchlist systems, the Knowledge
Graph, and Portfolio & Risk Intelligence, exposing `items`, `categories`,
`portfolioIntelligence`, `emergingThemes` (reused from
`buildKnowledgeInsights()`), and `graph` — the same "compose once, expose
downstream" pattern `useDecisionQualityEngine()` already established
(Sprint 19).

## 3. Integration points

1. **Command Centre** (`InstitutionalCommandCentre.tsx`) — new
   `MarketIntelligenceCard`: Today's Key Events, Upcoming Economic
   Releases, Watchlist Intelligence, Emerging Themes, Priority Items, plus
   a link to the full page.
2. **Research** — every item's Related Research links directly into the
   user's own research notebooks via the Knowledge Graph; nothing new is
   authored on the Research side.
3. **Decision Workflow** — Related Strategies surfaces linked strategies
   the same way the Decision Quality & Review Engine already does.
4. **Portfolio Intelligence** — the dedicated Portfolio Integration card on
   `/market-intelligence` shows `RiskIntelligenceReport.signals` verbatim.
5. **Knowledge Graph** — every item links outward into real, existing
   graph nodes; Emerging Themes reuses `buildKnowledgeInsights()` exactly.
6. **AI Coach** — `buildMarketIntelligenceCoachNarrative()` renders inline
   on each expanded item: Why This Matters, Affected Assets, Affected
   Holdings, Research to Review, Playbooks to Consider — never a price
   prediction or trading signal.

## 4. Entity model

```
MarketIntelligenceItem (backend, stateless)
  └─ enriched into ─▶ MarketIntelligenceView (frontend, per-user)
       ├─ isWatched / isPriority / relatedHoldings   (derived booleans/sets)
       ├─ relatedResearch[] / relatedStrategies[] / relatedLessons[]
       │     (walked via KnowledgeGraph's company:{SYMBOL} node)
       └─ relatedPlaybook  (static category → playbook id map)
```

13 categories (`MARKET_INTELLIGENCE_CATEGORIES`): Macro, Economic Events,
Central Banks, Earnings, Corporate Actions, Sector Trends*, Commodities*,
Currencies*, Indices, Volatility, Options Activity, Market Breadth,
Sentiment* — the 4 marked `*` are **honestly reserved**
(`dataAvailable: false`, with an explicit `unavailableReason`) since no
sector-performance series, commodity feed, currency/FX feed, or sentiment
index exists anywhere in this codebase today — the same disclosure
discipline `portfolioRiskIntelligence.ts`'s own `currency_exposure` signal
already established.

---

## 5. Future data providers

Every category is a plain string enum with a `dataAvailable` flag — a
future live provider (e.g. a real sector-performance feed, a commodities
API, an FX feed, a sentiment index) plugs in by:

1. Adding a real fetch function alongside `eventItem()`/`briefingItems()`/
   `optionsActivityItems()` in `lib/marketIntelligence.ts` (api-server).
2. Flipping that category's `dataAvailable` to `true` and clearing its
   `unavailableReason` in `MARKET_INTELLIGENCE_CATEGORY_META`.
3. Setting `dataSource: "LIVE"` on the items it produces, honestly
   distinguishing them from the `"SIMULATED"` items every other category
   produces today.

No other code changes are needed — the category filter, Command Centre
card, Knowledge Graph linking, Portfolio Integration, and AI Coach
narrative all already operate generically over whatever items the feed
contains.
