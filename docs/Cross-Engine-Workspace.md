# Cross-Engine Workspace

Phase 34 — Cross-Engine Orchestration & Unified Workspace. One workspace
spanning the Institutional Investing Engine and the Institutional Trading
Engine — global search, an extended recent-activity feed, cross-engine
tasks, quick actions, recent items, and workspace shortcuts.

**This is an orchestration and integration phase, not a strategy or signal
phase.** Nothing here implements or evaluates ICT, SMC, ASAD, Trader Bill's
method, Tom Nash's method, the Dunni Framework, or any other named
methodology. No automated entries or exits, no trading signals, no
forecasting, no AI predictions, no probability engines, no broker
execution, no new trading mathematics. Every figure on this page is a
direct read, count, tally, deterministic substring match, or simple
aggregate of data already generated by using the platform.

## Where to find it

`/cross-engine-workspace`, linked from the sidebar navigation, the Command
Palette (inherits the nav entry automatically), the Investing Executive
Dashboard, the Institutional Dashboard (Trading Engine), the Trading
Analytics Dashboard, the Executive Intelligence Hub, the Reporting Centre,
and the Learning Centre overview.

## What it is

Five tabs:

- **Overview** — top-level KPIs (reused directly from Phase 33's
  `ExecutiveOverview`, never recomputed), **Cross-Engine Tasks** (a small,
  honestly-bounded "needs attention" list), and **Cross-Engine Context**
  (a pure-navigation chain: Research → Portfolio → Committee → Trading →
  Strategy → Analytics → Reporting → Learning → Executive Review — the
  literal flow the phase brief names, letting a user move naturally
  between surfaces without duplicated navigation).
- **Search** — **Cross-Engine Search**, a deterministic, case-insensitive
  substring search over 9 already-persisted entity categories: Portfolios,
  Holdings, Research Notes, Committee Snapshots, Trade Plans, Trading
  Journal entries, Strategies, Reports, and Learning Topics. Never a
  semantic or AI search — no relevance scoring beyond "does the query
  substring literally appear in this row's own text." An empty query
  returns no results (this is a search, not a browse-everything dump).
- **Activity** — **Recent Activity**, a chronological merge of Phase 33's
  own Activity Timeline (committee snapshots, risk snapshots, optimisation
  reviews, research notes, saved reports, notifications) extended with 3
  new entry types this phase adds: Trade Plan creation, Strategy
  registration, and Learning Topic completion — newest first.
- **Recent Items** — **Cross-Engine Recent Items**: the single
  most-recently-created row per entity category, for a fast "jump back
  into where you left off." Distinct from the interleaved Activity
  timeline — this is one card per category, not a merged feed.
- **Shortcuts** — **Workspace Shortcuts** (a static list of primary
  cross-engine surfaces) and **Cross-Engine Quick Actions** (reused
  directly from the platform's own Quick Actions/Command Palette list —
  Open Research, Open Portfolio, Open Trade Plan, Open Strategy, Open
  Analytics, Open Report, Open Learning, Open Executive Dashboard, Open
  Executive Intelligence — pure navigation, zero new business logic).

## Workspace State

The active tab is deep-linkable via `?tab=overview|search|activity|recent|shortcuts`
(matching `ExecutiveIntelligence.tsx`'s own established precedent) **and**
persisted to `localStorage` (`cross-engine-workspace:last-tab`), so
returning to this page resumes the tab you were last on. This is the
entirety of "Workspace State" for this phase — no new backend table, no
new persisted server-side preference.

## Cross-Engine Tasks — how it avoids fabricating predictions

Every task is either a trivial count of an existing status column, or a
direct pass-through of a field an earlier phase's own analytics module
already computed:

| Task | Source |
|---|---|
| Unread notification(s) | `platform_notifications.is_read = false`, a plain count |
| Open position(s) missing a stop or target | `trading_positions` where `status = 'open'` and (`stop_price IS NULL` or `target_price IS NULL`) |
| Portfolio(s) with no holdings yet | `investing_portfolios` with zero matching `investing_holdings` rows |
| Strategy checklist(s) in progress | `TradingAnalyticsDashboard.strategyUsage.checklistsInProgress` (Phase 32, unmodified, reused as-is) |

A task only appears when its count is genuinely greater than zero — never
a fabricated zero-state task, never a forced non-empty list.

## Global Search — entity categories and their sources

| Category | Source table | Matched fields |
|---|---|---|
| Portfolio | `investing_portfolios` | name |
| Holding | `investing_holdings` | symbol |
| Research Note | `investing_research_notes` | symbol, note |
| Committee Snapshot | `investing_decision_snapshots` | symbol, recommendation |
| Trade Plan | `trading_trade_plans` | symbol, direction, status |
| Trading Journal | `trading_journal_entries` | title, content |
| Strategy | `trading_strategies` | name, description, category |
| Report | `institutional_reports` | title, reportType |
| Learning Topic | the shared `LEARNING_PATHS` catalog | title |

Each category is capped at 10 results. Learning Topics honestly report a
`null` `occurredAt` (the catalog is static content with no persisted
creation timestamp) rather than fabricating a fake "just now" timestamp.

## How this reuses Phase 33 (zero duplicated aggregation logic)

`lib/executiveIntelligence.ts` (Phase 33) is imported, never modified.
`GET /workspace/overview` calls the exact same
`loadExecutiveIntelligenceInputs()` / `buildInvestingAnalyticsDashboard()`
/ `buildTradingAnalyticsDashboard()` / `buildExecutiveIntelligenceHub()`
functions `GET /executive/intelligence` itself calls, and returns that
hub verbatim as the `intelligence` field alongside this phase's own new
`recentActivity`/`recentItems`/`tasks` fields. `buildWorkspaceActivityTimeline()`
calls Phase 33's own `buildActivityTimeline()` with a large cap to get
every entry, then merges in the 3 new entry types and re-sorts/re-caps —
`executiveIntelligence.ts` itself is not touched.

## What it deliberately does not do

- No trading signal, probability, or prediction of any kind, anywhere on
  this workspace.
- No automated entries, exits, or broker execution.
- No semantic or AI search — deterministic substring matching only.
- No new business logic in Quick Actions or Shortcuts — every entry is a
  pure navigation link to an already-existing page.
- No new database table — every figure is read live from tables each
  engine's own analytics module already reads, plus the same 9 tables
  Global Search reads directly.

across 8 existing surfaces, and `docs/Cross-Engine-Orchestration.md` for
