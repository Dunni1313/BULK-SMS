# v1.6.0 Sprint 3 — UX Transformation

## Objective

Stop adding functionality. Make the platform feel like one connected
product instead of ~89 individual pages — Apple/Linear/Notion/Bloomberg-
Terminal-grade polish, not new capability. This sprint explicitly replaced
the originally-planned "Sprint 3: Adaptive Workspace & Dynamic Command
Centre" (Focus Mode, Workspace Memory, Context Panel — all deferred to the
Version 2.0 backlog, per direct instruction) with a pure usability,
navigation, and consistency pass, built entirely on existing architecture.

## Investigation before any code

Before writing anything, three parallel investigation passes established
what already existed, so nothing here duplicates prior work:

- **`PlatformJourneyNav`** (`components/layout/PlatformJourneyNav.tsx`,
  v1.5.0 Sprint 11–14) already IS "one visual workflow available
  everywhere" — a 12-stage cross-module journey (Research → Notebook →
  Strategy → Trade Plan → Decision → Execute → Open Position → Trade
  Management → Trade Journal → Performance Review → Portfolio Impact →
  Continuous Learning), already mounted on 8 pages. This sprint **expanded
  it, never duplicated it.**
- A **separate, deliberately distinct** day-level "Daily Workflow" system
  (`lib/ai-coach/tradingCoachWorkflow.ts`, v1.6.0 Sprint 1/2) already
  exists and must never be confused with the above — two genuinely
  different concepts (module journey vs. daily task list), both already
  reused across multiple pages. **No third workflow concept was created.**
- **No PageHeader/PageIntro component existed anywhere.** 66 of 89
  top-level pages hand-roll the identical header shape (icon + `<h1
  className="text-2xl font-bold">` + badge row + description paragraph) —
  a copy-pasted convention, not a shared component.
- **No tour/walkthrough library exists** in `package.json` (no
  joyride/driver.js/intro.js/shepherd/reactour) — only unused,
  dead-on-arrival tour-adjacent fields (`guidedTourRequired` on
  `LearningTopic`, never read anywhere). Existing Radix primitives
  (Dialog, Progress, Popover, Tooltip) were reused instead of adding a
  library.
- **`ModuleLearnTrigger`/`ModuleLearnDrawer`** (v1.5.0 Sprint 11) is
  already the platform's de facto contextual-help pattern, backed by
  `lib/learn/moduleLearnRegistry.ts` — a pure lookup table into the
  existing Learning Centre content (`lib/learningPaths.ts`, 15 paths, 119+
  topics), explicitly "NOT a new content system." Extended, never
  replaced.
- The `nav-items.ts` sidebar (94 items, 10 logical groups, v1.1.0
  redesign) was found **already well-organized** — every genuinely
  similar-sounding pair (Institutional Command Centre vs. Options Command
  Center; Trading Journal vs. Trade Journal; Market Scanner vs. Stock
  Scanner) is an intentional, previously-disclosed Engine 1/2/3
  disambiguation, not an accidental duplicate. A wholesale restructuring
  was judged unnecessary and risky; the real fix for "every page has one
  obvious purpose" was the new `PageShell`'s own title/description/why-
  it-matters block, not renaming routes.

## What was built

### 1. `PageShell` — the one reusable page shell

New `components/layout/PageShell.tsx`. Replaces each migrated page's own
hand-rolled header with one shared component providing exactly the 6
things the approved scope named:

- **Title** (icon + `<h1>`, same visual convention as before — a drop-in
  replacement, not a new visual language).
- **Short description** (always visible, never hidden).
- **"Why this matters"** — collapsed by default behind an "About this
  page" toggle (progressive disclosure: professional users who already
  know the platform never see it unless they ask).
- **Current workflow step** — a thin wrapper around the *existing,
  unmodified* `PlatformJourneyNav`, rendered only when the page names a
  real `journeyStage` (never a fabricated stage for a page that isn't
  part of the journey).
- **Next recommended action** — derived directly from
  `PLATFORM_JOURNEY_STAGES`' own already-existing stage/href list (finds
  the next stage after the current one with a real link) — never
  fabricated copy.
- **Related modules** — derived directly from the existing `NAV_GROUPS`
  sidebar index (sibling items in the same nav group as the current
  route) — no second "related content" registry invented.

Also renders a "back to Command Centre" link on every non-home page
(Command Centre reinforcement) and a real `ModuleLearnTrigger` when a
`learnEntryId` resolves to a real, already-existing Learning Centre entry.

`description` accepts `React.ReactNode`, not just a string, since several
migrated pages' own descriptions carry real cross-links (with their own
pre-existing `data-testid`s) that had to be preserved exactly.

### 2. `PlatformJourneyNav` expansion — one new "Discover" stage

The existing 12-stage journey started at "Research," with no
front-of-journey stage for opportunity discovery. Per the approved scope's
explicit "expand it where appropriate, do NOT create another workflow
component," one new stage — **Discover** (→ `/scanner`) — was inserted at
the front, the same incremental, disclosed-in-code-comments pattern
Sprints 12–14 already used three times for this exact component. Every
pre-existing stage id/label/href is unchanged; `InstitutionalCommandCentre.tsx`'s
own richer per-stage Workflow Panel gained a matching "Discover" tile,
reusing the already-fetched `useOpportunityPipeline()` hook (no new
provider call).

### 3. Guided Tours

New `lib/guided-tours.ts` (content registry) + `components/tour/GuidedTourDialog.tsx`
+ `components/tour/GuidedTourTrigger.tsx`. The 4 tours named in the
approved scope — **First Trade, First Research, First Journal, First
Portfolio Review** — each 3–5 steps, "learn by doing": every step that
names a destination links to a real, already-existing route. Built
entirely from existing shadcn/ui `Dialog`/`Progress`/`Button` primitives
(no new library). Completion tracked with the exact same localStorage
idiom already established by `AiTradingCoachPanel`'s own onboarding
dismissal (Sprint 1/2) and `lib/workflow-dismissals.ts` — one string
constant key, a JSON array of completed ids, try/catch fail-open. Mounted
on the Institutional Command Centre, right next to Quick Actions,
reinforcing "every workflow naturally begins there."

### 4. Contextual Help extension

5 new entries added to `lib/learn/moduleLearnRegistry.ts` (`command-centre`,
`discover`, `decision-workflow`, `execution-lifecycle`,
`portfolio-review`) — every `pathKey`/`topicKey` pair points at an
already-existing Learning Centre topic (`platform-basics` and
`professional-workflows` paths), following the registry's own established
"one-line addition, never a new lesson" precedent. Zero new financial or
platform-navigation content was authored.

## Pages migrated to `PageShell`

A deliberately bounded "golden path" slice — the daily-workflow chain
already codified twice in the existing codebase (both `PlatformJourneyNav`'s
stage list and the Daily Workflow engine's own step→route mapping) — not
all 89 pages in one pass, matching this project's own established
"first bounded slice" precedent:

| Page | Route | `journeyStage` | `learnEntryId` |
|---|---|---|---|
| Scanner | `/scanner` | `discover` | `discover` |
| Opportunity Pipeline | `/opportunity-pipeline` | `discover` | `discover` |
| Decision Workflow | `/decision-workflow` | `decision` | `decision-workflow` |
| Execution & Lifecycle Manager | `/execution-lifecycle` | `open-position` | `execution-lifecycle` |
| Institutional Mentor | `/institutional-mentor` | `learning` | `portfolio-review` |
| Cross-Engine Daily Report | `/daily-report` | `performance` | — |

**Deliberately not migrated, and why (disclosed, not an oversight):**

- **`TradeExecutionCenter.tsx`** — has its own deliberate all-caps
  branding and its own step-specific `<Stepper>` (candidate → ticket →
  confirm), a more specific "where am I" indicator than the module-level
  journey nav would add. Forcing `PageShell`'s convention here would be
  cosmetic redesign for its own sake, explicitly forbidden by the approved
  scope ("do not redesign simply for appearance").
- **`TradePlanningStudio.tsx` / `ResearchTerminal.tsx` / `InstitutionalWorkspace.tsx`**
  — dense, resizable-multi-panel "studio" layouts, already confirmed (by
  a prior sprint's own Phase 23 audit) as an intentional deviation from
  the standard page-header convention. Not touched.
- **`TradingJournal.tsx`, `TradingResearch.tsx`, `PortfolioDashboard.tsx`**
  — already had `PlatformJourneyNav` mounted plus a `ModuleLearnTrigger`
  and a clear title/badge row; reviewed against the 4 first-time-user
  questions and found to already answer all of them. No change needed —
  the "smallest possible improvement" was none.

`CrossEngineDailyReport.tsx` and `Scanner.tsx`/`OpportunityPipeline.tsx`/
`DecisionWorkflow.tsx`/`ExecutionLifecycleManager.tsx` also gained
`AiTradingCoachPanel` where it was the one Daily-Workflow-step destination
still missing it (`CrossEngineDailyReport.tsx` — the `daily-review` step's
own destination).

## Final UX / consistency / design review (pre-PR)

Walked the full golden path (Command Centre → Scanner → Research → Trade
Planner → Decision Review → Execution → Portfolio → Journal → Daily
Review) as a first-time user, asking the 4 approved questions on each
page. `PageShell` adoption is itself the single highest-leverage
consistency fix: every migrated page now shares identical title/badge/
description placement, an identical progressive-disclosure "About this
page" pattern, an identical journey indicator, and an identical Learn
trigger — a real, structural reduction in duplicated header
implementations, not just a documentation claim. Pages outside the
bounded slice were spot-checked (see the "deliberately not migrated"
table above) and found to already meet the bar or to be a defensible,
disclosed exception.

## Known limitations / future UX backlog

- Only 6 of ~89 pages were fully migrated to `PageShell` this sprint — a
  disclosed, bounded first slice. A future sprint could extend `PageShell`
  adoption further down the nav tree.
- Sidebar structure itself (`nav-items.ts`'s 10 groups) was reviewed and
  found already sound; no restructuring was done. A future sprint could
  add short one-line `description` hints to more nav items if a genuine
  need surfaces.
- The Adaptive Workspace, Focus Mode, Workspace Memory, and Context Panel
  ideas from the original Sprint 3 proposal remain in the Version 2.0
  backlog, per explicit instruction — not attempted here.
- Guided Tours are dialog-based (Next/Back/Skip/Done), not a DOM-spotlight
  overlay — a deliberate, disclosed design choice to avoid the fragility
  of measuring arbitrary element bounding rects, and to avoid introducing
  a new tour library.

## What was explicitly NOT done

No new AI systems, no new workflow engine, no duplicated components, no
new trading features, no removed functionality. `execution.ts`,
`optionsMath.ts`, `risk.ts`, `autoExecution.ts`, `autoAdjustment.ts` all
remain zero-line diff.
