# v1.5.0 Sprint 7 — AI Workspaces

Branch: `v1.5.0-sprint-07-ai-workspaces` (stacked on `v1.5.0-sprint-06-ai-coach-memory`)

## What this sprint adds

Reusable **AI Workspaces** for the three existing conversational AI Coaches
(Trading, Investing, Options). A workspace groups multiple conversations,
saved research (quick notes, AI summaries, conclusions, action items), file
references, and tags into a single, reusable research project. Portfolio has
no conversational coach (an exhaustive Sprint 3 finding) and has nothing
registered here.

This is a user-facing productivity feature built entirely on top of Sprint
6's conversation memory — it does not touch trading logic, investing logic,
options calculations, the execution engine, the risk engine, prompts, tool
permissions, authentication, broker integrations, or Portfolio Coach.

## Architecture

### Backend

- **Reuse, not duplication.** Per the approved scope ("reuse Sprint 6 tables
  where possible, do not duplicate conversation storage"), conversations
  themselves are never re-stored. Sprint 6's existing
  `ai_coach_conversations` table gained two small, additive, nullable/
  default-safe columns instead:
  - `workspace_id` (nullable integer, `ON DELETE SET NULL`) — optional
    workspace membership. Nullable so every pre-existing conversation keeps
    working identically.
  - `favourite` (boolean, default `false`) — a plain per-conversation flag,
    independent of workspace membership.
- **Three brand-new tables** (migration `040_ai_workspaces.sql`):
  - `ai_workspaces` — one row per workspace (name, description, coach_id,
    pinned, archived, tags array, timestamps).
  - `ai_workspace_files` — file **references only** (a name + an external
    URL + an optional note). This codebase has no binary file-upload/
    storage infrastructure anywhere, and building one was explicitly out of
    this sprint's scope — never a fabricated upload capability.
  - `ai_workspace_notes` — one table discriminated by `kind`
    (`note` | `summary` | `conclusion` | `action_item`) rather than four
    separate tables, matching this codebase's own established free-text-
    discriminator convention (e.g. `investing_filing_analysis.filing_type`).
- **Deletion semantics, deliberately asymmetric:**
  - Deleting a workspace **cascades** its own `ai_workspace_files`/
    `ai_workspace_notes` rows (`ON DELETE CASCADE`) — they have no meaning
    independent of the workspace they belong to.
  - Deleting a workspace **detaches, never destroys**, its conversations
    (`ai_coach_conversations.workspace_id → NULL`, `ON DELETE SET NULL`) —
    the conversation and its full message history remain fully intact and
    resumable from the top-level, un-grouped conversation list. This is a
    hard requirement: "Existing conversation functionality unchanged" must
    hold even for a deleted workspace's own former conversations.
- **New route file** `routes/aiWorkspaces.ts` — full CRUD for workspaces
  plus their nested conversations/files/notes, mounted alongside (not
  replacing) `routes/aiCoachConversations.ts`. Deliberately kept outside the
  OpenAPI/orval typed contract and validated via the same small,
  hand-written plain-validation functions Sprint 6 established (avoiding
  the exact zod-dependency-conflict risk that sprint's own validation
  disclosed).
- **`routes/aiCoachConversations.ts` extended additively:**
  - `formatConversation()` now includes `workspaceId`/`favourite`.
  - `GET /coach-conversations` gained an optional `?workspaceId=` filter —
    omitting it preserves Sprint 6's exact original behavior.
  - `POST`/`PATCH /coach-conversations[/:id]` accept an optional
    `workspaceId`, validated against ownership and coach-type match (a
    Trading conversation can never be filed under an Investing workspace).
  - A new exported `createConversationRow()` is the single insert point
    both routes share, and a new exported `loadOwnedWorkspace()` is shared
    by both route files.

### Frontend

- `src/lib/ai-coach/workspacesApi.ts` — plain-fetch client for
  `/ai-workspaces[...]`, mirroring `coachConversationsApi.ts`'s own
  established pattern.
- `src/lib/ai-coach/coachConversationsApi.ts` extended additively:
  `CoachConversation` gained `workspaceId`/`favourite`; `listConversations`/
  `createConversation` gained optional `workspaceId` params (omitting them
  preserves the exact original call shape); new `setConversationFavourite`/
  `assignConversationToWorkspace` exports.
- `src/lib/ai-coach/useAiWorkspaces.ts` — the workspace-memory hook for one
  coach, mirroring `useCoachConversations.ts`'s own shape: workspace list,
  active-workspace selection + its full detail (conversations summary/
  files/notes), search, includeArchived toggle, and CRUD/pin/archive/
  delete/notes/files actions.
- `src/lib/ai-coach/useCoachConversations.ts` extended additively with one
  new, optional `workspaceId` parameter. Omitting it (every pre-Sprint-7
  call site) preserves the exact original behavior byte-for-byte. New
  `toggleFavouriteById`/`assignConversationToWorkspaceById` actions.
- `src/lib/ai-coach/ConversationSidebar.tsx` gained one new, optional
  `onToggleFavourite` prop — a star toggle per conversation. Omitting it
  renders exactly as before Sprint 7.

## Data model

```
ai_workspaces
  id, user_id (FK → users, RESTRICT), coach_id, name, description,
  pinned, archived, tags[], created_at, updated_at

ai_coach_conversations (Sprint 6, extended)
  ... existing columns unchanged ...
  workspace_id (FK → ai_workspaces, SET NULL, nullable)
  favourite (boolean, default false)

ai_workspace_files
  id, workspace_id (FK → ai_workspaces, CASCADE), file_name, file_url,
  note, created_at

ai_workspace_notes
  id, workspace_id (FK → ai_workspaces, CASCADE), kind, content, created_at
```

Neither `ai_workspace_files` nor `ai_workspace_notes` carries its own
`user_id` — ownership is transitive via `workspace_id → ai_workspaces.user_id`,
the same no-redundant-denormalization pattern `ai_coach_messages` already
established relative to `ai_coach_conversations.user_id` (Sprint 6).

## Workspace lifecycle

```
Create Workspace
      │
      ▼
Open Workspace  ───────────────► "All conversations" (no workspace selected)
      │                                  │
      ▼                                  ▼
Start new AI conversation      Every un-grouped conversation for this coach
(pre-assigned to workspace)
      │
      ▼
Resume previous conversations (scoped to this workspace)
      │
      ▼
Attach research (files: name + URL; notes: quick note / AI summary /
conclusion / action item)
      │
      ▼
Save AI summaries (one of the 4 note kinds)
      │
      ▼
Continue later (workspace + its conversations + research persist)
```

Pin, archive, and delete are available at any point. Archiving hides a
workspace from the default list (still retrievable via `includeArchived`).
Deleting a workspace cascades its files/notes but only *detaches* its
conversations — they remain in the top-level list, fully resumable.

A conversation can independently be:
- **Assigned** to a workspace of the *same coach* (or unassigned via
  `workspaceId: null`).
- **Favourited** (a star, independent of workspace membership).

## UI

Five new, genuinely reusable components in `src/lib/ai-coach/`:

- **`WorkspaceSidebar`** — the workspace list: search, inline "New
  Workspace" create form (name + optional description), pin/archive/delete
  quick actions per card, "All conversations" clear-selection entry, and an
  honest empty state.
- **`WorkspaceSelector`** — a compact, single-value workspace switcher (a
  plain native `<select>`, deliberately not the app's Radix-based `Select`
  component — a single-value picker needs no popover/portal behavior, and a
  native element is trivially and reliably testable via `fireEvent.change`).
  Built for future reuse; not currently wired into a page (see Future
  Roadmap).
- **`WorkspaceHeader`** — shown above the conversation panel once a
  workspace is active: name/description/tags, pin/archive/delete, and a
  collapsible "Research" panel (quick notes / AI summaries / conclusions /
  action items, plus file references).
- **`WorkspaceCard`** — a single workspace's summary card, reused inside
  `WorkspaceSidebar`'s own list.
- **`WorkspaceEmptyState`** — a small, generic "nothing here yet" state
  reused wherever a workspace-scoped list is empty.

`ConversationSidebar` (Sprint 6) is reused unmodified except for its one new
optional `onToggleFavourite` prop, exactly as instructed ("Reuse the Sprint
6 Conversation Sidebar where appropriate").

### Page integration

All three coach pages (`Assistant.tsx` — Options, `TradingResearch.tsx` —
Trading, `StockResearch.tsx` — Investing) were extended identically:
`WorkspaceSidebar` is stacked above the existing `ConversationSidebar` in
the same column; `WorkspaceHeader` renders above the message panel whenever
a workspace is active. `useCoachConversations(coachId, activeWorkspaceId ??
undefined)` scopes the conversation list to the active workspace, or shows
every un-grouped conversation when none is selected — Sprint 6's exact
original "All conversations" behavior.

## Search

- **Workspace search** — `WorkspaceSidebar`'s search box filters the
  workspace list by name (case-insensitive substring match), server-side
  via `GET /ai-workspaces?search=`.
- **Conversation search** — unchanged from Sprint 6: `ConversationSidebar`'s
  own search box filters by title within whichever scope is active (a
  specific workspace, or "All conversations").
- Both searches are independent and compose naturally — searching within a
  workspace searches only that workspace's own conversations.

## Privacy

- Every workspace/file/note read, create, update, and delete is scoped by
  `(user_id, coach_id)` for workspaces, and transitively by workspace
  ownership for files/notes — the same isolation discipline Sprint 6
  established. 404, never a separate 403, for both "doesn't exist" and
  "isn't yours" or "belongs to a different coach."
- A workspace belongs to exactly one coach; a conversation can only be
  assigned to a workspace of its own coach (enforced server-side on both
  `POST`/`PATCH /coach-conversations[...]`).
- File references store only a name, an external URL, and an optional
  note — never a binary upload, never a secret.
- Notes store only the free text a user actually typed — no internal
  prompt, tool/grounding-context payload, or secret is ever persisted,
  matching Sprint 6's own established discipline for messages.

## Future roadmap

- **`WorkspaceSelector` is built but not yet wired into a page.** It's a
  natural fit for a more compact, single-line workspace switcher (e.g. in a
  page header) as an alternative to the fuller `WorkspaceSidebar`, once a
  concrete UI need for that density is identified.
- **Drag-and-drop conversation reassignment** between workspaces (currently
  requires opening a conversation and using an assign action) is a natural
  future enhancement once the underlying `assignConversationToWorkspaceById`
  action already exists.
- **Cross-workspace search** ("search all my workspaces for X") is not yet
  built — today's search is scoped to one list at a time (workspaces, or
  one workspace's conversations).
- **Shared/team workspaces** are explicitly out of scope for this sprint —
  every workspace is single-user, matching every other user-scoped table
  in this codebase.
- **Workspace templates** (e.g. a pre-configured "Earnings Season" research
  project) could be layered on top of the existing create-workspace flow
  without any schema change.
