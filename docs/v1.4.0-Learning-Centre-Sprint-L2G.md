# v1.4.0 — Learning Centre Sprint L2G: Options Strategies Academy

**Branch:** `v1.4.0-learning-centre-l2g` (off `main`, post-Sprint-L2F merge
commit `ba79a05`)
**Scope, as explicitly approved:** build the Options Strategies Academy,
teaching users how to understand, evaluate, and execute the options
strategies already implemented in the platform — teaching how to use the
platform's strategy tools, never inventing new trading engines or strategy
logic. Mandatory first step: inspect the actual Options Strategy Engine
implementation before writing any lessons. Do not merge into `main`. Open
a Pull Request and wait for approval.

---

## 1. Objective

Unlike prior Academy sprints, this one had a mandatory first step baked
directly into the brief: inspect the real strategy engine, identify every
strategy currently supported, and clearly identify any requested strategy
concept that is educational-only or not implemented at all — never
inventing a screen, calculation, workflow, or broker capability.

## 2. Strategy engine inspection (the implementation map)

Two parallel, read-only investigation passes were run before any content
was written — one covering `optionsMath.ts`/`execution.ts`'s actual
strategy-building functions and routing, one covering the pre-existing
Learning Centre `strategies` path, glossary, and the separately-existing
Strategy Academy page. Key findings, each independently confirmed by
direct source inspection:

- **The single most important finding of this sprint:** the platform's
  execution/scanning engine structurally builds and prices **only three
  strategies** — Iron Condor (`buildIronCondor`, `optionsMath.ts:475-525`),
  Iron Fly / Iron Butterfly (`buildIronFly`, `optionsMath.ts:527-576`), and
  Calendar Spread (`buildCalendar`, `optionsMath.ts:578-623`, calls-only
  construction) — plus "Earnings" (`buildEarnings`) as an Iron-Fly
  parameterization with elevated pre-earnings IV. `execution.ts:51`'s
  `Strategy` union type — `"iron_condor" | "iron_fly" | "calendar_spread" |
  "earnings"` — is the exhaustive, authoritative list, confirmed against
  `Scanner.tsx:60-64`'s own strategy filter (exactly those four values,
  zero delta/wing/DTE controls anywhere in the UI, confirmed by direct
  grep) and `optionsStrategyLibrary.ts`'s own `executionStrategyKey`
  mapping (every other strategy template maps to `null`).
- A substantial pre-existing **Strategy Academy** page already exists
  (`/learn/strategy-academy`, backed by `strategyAcademy.ts`) covering 8
  strategies — Covered Call, Cash Secured Put, Wheel, Vertical Spread, Iron
  Condor, Iron Fly, Calendar Spread, Diagonal Spread — each carrying its
  own `builtByThisEngine: boolean` flag, and only 3 (`iron_condor`,
  `iron_fly`, `calendar_spread`) generate a real, live worked example; the
  other 5 honestly render `buildUnavailableExample()`'s disclosed
  "conceptual education only" message. This is the same honesty pattern
  Sprint L2F's own `foundations-options` topic first established, now
  confirmed as an already-reviewed, already-tested platform precedent.
- The pre-existing `strategies` LearningPath (`learningPaths.ts:707-793`,
  8 thin, plain stub topics predating the Sprint L1+ rich-content pattern)
  almost exactly maps onto this sprint's 8 requested modules — 5 direct
  upgrade targets (Covered Call, Vertical Spreads, Iron Condor, Iron Fly,
  Calendar Spread) plus 3 genuinely missing topics (Long Call, Long Put,
  Protective Put) that needed to be created new. `strategies-csp`
  (Cash Secured Put), `strategies-wheel` (The Wheel), and
  `strategies-diagonal` (Diagonal Spread) were **not requested this
  sprint** and remain completely untouched, plain stub topics.
- A real, routed **Payoff Diagram Simulator** exists (Learning Centre's
  Simulations tab, `LearningCentre.tsx`) covering Covered Call, Cash
  Secured Put, and Iron Condor with hypothetical, user-supplied inputs —
  explicitly labeled "Educational Simulation — Not Market Data — No Trade
  Recommendation." This is genuine, useful platform grounding for the
  Covered Call lesson, confirmed by direct inspection before being cited.
- **Protective Put has zero implementation anywhere in this codebase** —
  no execution builder, no Strategy Academy entry, no glossary key, no
  simulator support, no prior `learningPaths.ts` reference of any kind.
  This is the sprint's one genuinely from-scratch, conceptual-only lesson.

## 4. Design decisions made during implementation

- **Upgrade-in-place vs. new topic, decided per-strategy against real
  platform status**, mirroring the precedent Sprint L2A-F established:
  Covered Call/Vertical Spreads/Iron Condor/Iron Fly/Calendar Spread all
  had existing stub keys and were upgraded in place, preserving every key.
  Long Call, Long Put, and Protective Put had no prior topic and were
  added as brand-new `strategies-*` topics.
- **The genuinely useful, honest cross-connection this sprint surfaces**:
  the Vertical Spreads lesson explicitly teaches that a real Iron Condor's
  put side *is* a bull put spread and its call side *is* a bear call
  spread — a real, verified structural fact (confirmed directly against
  `buildIronCondor()`'s own leg construction), not a fabricated
  simplification. The two debit variants (bull call, bear put) have no
  such connection and are disclosed as pure theory with no platform
  workflow.
- **Long Call and Long Put are taught with full strategy-lesson depth**
  (market outlook, max profit/loss, breakeven, Greeks, risk profile) while
  being explicit, in the Platform Implementation section of each, that
  neither is a strategy this platform's scanner or execution engine
  builds, prices, or trades — only the Option Chain's live per-strike
  pricing is real platform grounding.
- **Covered Call leans on two genuinely real platform features**
  (the Strategy Academy reference page and the Payoff Diagram Simulator)
  rather than inventing a scanner/execution workflow that doesn't exist —
  satisfying the brief's own "if not implemented, document this clearly
  rather than inventing functionality" instruction for a strategy that
  does have real, if education-only, platform support.
- **Protective Put has zero platform implementation to lean on at all**
  — the lesson is explicit and repeated about this (no Strategy Academy
  entry, no simulator support, no prior glossary precedent), teaching the
  real hedging concept purely as theory.
- **New glossary terms**: `long-call`, `long-put`, `protective-put`,
  `bull-call-spread`, `bear-put-spread`, `bull-put-spread`,
  `bear-call-spread`, `wing-width` — all category `strategies`. The
  existing `vertical-spread` and `covered-call` entries received small,
  disclosed factual enrichments (the 4 named variants, and the
  execution-engine-non-support disclosure respectively) — the same
  established pattern as Sprint L2F's `historical-volatility`/`event-risk`
  corrections.
- **`nextStepKeys` same-path constraint, re-confirmed this sprint**: the
  test enforces this only within the `platform-basics` path's own describe
  block, not globally — but every `nextStepKeys` chain added this sprint
  was deliberately kept within the `strategies` path anyway (Long Call →
  Long Put → Protective Put → [end]; Vertical Spreads → Iron Condor → Iron
  Fly → Calendar Spread → [end]; Covered Call → Protective Put), matching
  the established discipline from prior sprints regardless of whether the
  test technically enforces it here.
- **Worked-example count constraint, re-confirmed**: exactly 3 worked
  examples labeled `["Good Opportunity", "Average Opportunity", "Poor
  Opportunity"]` per module-guide topic. All 8 new/upgraded topics verified
  via script before running any test.
- **One real type error caught during validation, not anticipated in the
  pre-approval plan**: the `topic()` helper's TypeScript signature only
  accepts `externalHref?: string` (optional, string-only) — an explicit
  `externalHref: null` on the Protective Put topic (correct at runtime,
  since the helper's own default is `null`) failed `tsc` with `TS2322:
  Type 'null' is not assignable to type 'string | undefined'`. Fixed by
  omitting the field entirely, letting the helper's own default apply —
  zero behavior change, a pure type-signature correction.

## 7. Educational concepts intentionally left as references (not implemented)

- Long Call and Long Put as standalone, order-routable trades — no
  execution builder exists for either; only the Option Chain's live
  per-strike pricing is real.
- Protective Put — zero implementation anywhere: no scanner, no execution
  builder, no Strategy Academy entry, no simulator support.
- All four named vertical-spread variants (Bull Call, Bear Put, Bull Put,
  Bear Call) as standalone orders — none is independently order-routable;
  only the combined four-leg Iron Condor and Iron Fly structures are.
- A standalone Covered Call order — the execution engine does not build
  or price it; only the Strategy Academy reference page and Payoff Diagram
  Simulator exist as education-only support.
- Manually adjustable wing width or delta selection beyond what
  `buildIronCondor`/`buildIronFly` actually expose (`shortDelta`, `dte`
  only) — wing width is always auto-computed by formula, never a UI input.
- A put-based calendar spread variant — `buildCalendar()`'s construction
  is calls-only; no put variant exists in this engine.
