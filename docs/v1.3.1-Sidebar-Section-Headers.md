# v1.3.1 — Sidebar Section Headers

A small, isolated visual enhancement to the sidebar built ahead of the AI
Trading Coach UI (v1.3.1 branch), replacing the plain-text section labels
introduced by the v1.1.0 Sidebar Navigation Redesign
(`docs/v1.1.0-Sidebar-Navigation-Redesign.md`) with full-width, coloured
header bars.

## What changed

Before this change, each of the sidebar's 10 collapsible `NAV_GROUPS`
sections rendered its label as a plain `<button>` styled with a shared
`GROUP_HEADER_CLASS` string (small uppercase text, a hover background, no
colour distinction between groups). This change replaces that markup with
a new, reusable `SidebarSectionHeader` component that renders a full-width,
coloured bar per group, themed by engine.

Nothing about the underlying navigation data, routing, accordion state, or
permissions changed — this is presentation-only.

## Files created

- `artifacts/ravish-trading/src/components/layout/SidebarSectionHeader.tsx`
  — the new reusable header-bar component. Renders in two modes:
  - **Interactive** (the default): a `<button>` with `aria-expanded` and a
    rotating chevron, used as the `CollapsibleTrigger` for each of the 10
    `NAV_GROUPS` sections. Built with `React.forwardRef` so it composes
    correctly as the child of Radix's `<CollapsibleTrigger asChild>`
    (which clones its child and injects `ref`/`aria-expanded`/`data-state`/
    `onClick`).
  - **Non-interactive** (`interactive={false}`): a plain, non-focusable
    `<div>` with no chevron and no `aria-expanded`, used only for the
    static "Frequently Used" pinned-items header, which has never been
    collapsible and isn't becoming so here.
- `artifacts/ravish-trading/src/components/layout/SidebarSectionHeader.test.tsx`
  — isolated unit tests for the component itself (theme classes, collapsed
  vs. expanded chevron/`aria-expanded` state, keyboard focusability,
  arbitrary prop pass-through, the non-interactive rendering path, and the
  compact-mode hide rule).

## Component reused / created

`SidebarSectionHeader` did not previously exist and was created new, per
the request's own requirement #4 ("Create a reusable `SidebarSectionHeader`
component if an equivalent component does not already exist"). It is a
pure presentation component: it owns no navigation data, no accordion
state, and no routing — all of that continues to live in `nav-items.ts`
and `SidebarNav.tsx`, exactly as before. The 10 `NAV_GROUPS` entries and
the "Frequently Used" pinned list are the *only* two call sites; no
navigation logic was duplicated.

### Contrast-ratio derivation

The existing design-system tokens (`--success`, `--primary`, `--chart-4`,
etc.) are tuned for use as a small accent colour shown *against* the dark
sidebar background — not as a full bar background that itself needs to
host readable white text. Using them directly would only clear roughly a
2–3:1 contrast ratio against white, well under WCAG AA's 4.5:1 minimum for
normal-size text (bold alone does not qualify text as "large" under WCAG
unless it is at least ~18.66px, and this header text is `text-xs`/12px).

Each of the 5 new background values above was chosen by manually computing
HSL → RGB → relative luminance → contrast ratio against pure white
(`0 0% 100%`), and darkening/desaturating each candidate hue until it
cleared 4.5:1. All 5 clear the bar with meaningful margin (each computes to
roughly 7:1–9:1 against white), giving headroom for the `hover:brightness-110`
hover effect without dropping below the AA threshold.

## Visual description

Each section header now renders as a solid-coloured, full-width rounded
bar (10px corner radius) spanning the sidebar's full available width —
achieved via a negative margin (`-mx-2`) with no explicit width utility, so
the box's default block auto-width naturally bleeds past the parent
`SidebarGroup`'s own `p-2` padding to the sidebar's true edge. Each bar
shows a left-aligned icon (matching the icon already used elsewhere for
that group), bold uppercase text, and — for the 10 collapsible groups only
— a chevron on the right that rotates 90° when the section is expanded.
Hover applies a `brightness-110` filter; expand/collapse continues to use
the pre-existing `animate-collapsible-down`/`animate-collapsible-up`
keyframe animations (`index.css`, unchanged) driven by Radix's own
`CollapsibleContent`. In compact (icon-only) sidebar mode, every header bar
is hidden entirely via `group-data-[collapsible=icon]:hidden` — matching
the pre-existing behaviour where compact mode shows one continuous icon
stack per group with no header chrome at all.

## Preserved behaviour

- **Routes** — unchanged; `nav-items.ts`'s `NAV_GROUPS`/`ALL_NAV_ITEMS`
  route list is untouched (only the new `theme` field was added).
- **Permissions** — unchanged; no route gating logic lives in this file.
- **Collapsed-sidebar (compact) behaviour** — unchanged; headers hide via
  the same `group-data-[collapsible=icon]:hidden` rule the old
  `GROUP_HEADER_CLASS` already used.
- **Mobile responsiveness** — unchanged; `SidebarNav.tsx`'s mobile-specific
  logic (`handleNavigate()`'s `setOpenMobile(false)` call) is untouched.
- **Active navigation states** — unchanged; `activeGroupId`-driven
  force-expand logic in `SidebarNav.tsx` is untouched, and the header bar
  correctly reflects `aria-expanded="true"` when its group is force-expanded
  by an active child route.
- **Keyboard navigation** — the interactive header renders as a real
  `<button type="button">`, so it remains natively focusable and
  Enter/Space-activatable exactly as the old plain `<button>` was.
- **Accessibility labels** — the header's accessible name comes from its
  own visible label text (no `aria-label` needed, since the label is
  already the button's text content); `aria-expanded` is set correctly for
  both states; a `focus-visible` ring is preserved.
