# Version 1.5.0 — Sprint 1: AI Coach Architecture Consolidation

**Branch:** `v1.5.0-sprint-01-ai-coach-consolidation`
**Status:** Implemented, validated, PR opened against `main`. Not merged — awaiting explicit approval.

## Sprint objective

Improve architecture, consistency, and maintainability of the platform's AI Coach
surfaces without introducing new user-facing features. The concrete, reported
problem was a naming collision between two genuinely different coach systems
that both ended up with confusingly similar names:

- `/trading-ai-coach` — **"Trading AI Coach"** (Phase 29 / Phase 3 Sprint 47) — a
  deterministic, per-topic explanation engine (Structure/Liquidity/Session/Risk/
  Trade Plan/Journal/Psychology "coaches"), zero LLM narration of its own free-form
  Q&A endpoint aside, plus a genuine free-form Q&A pair reusing `narrateTradeFreeform`.
- `/ai-trading-coach` — **"AI Trading Coach"** (v1.3.0 Sprint 1) — a unified,
  cross-engine, LLM-narrated free-form chat assistant with server-persisted
  conversation history (`trading_coach_messages`), reachable both as its own
  page and as a dockable panel from anywhere in the app.

Both names differ only in word order ("Trading AI Coach" vs. "AI Trading
Coach"), which is the literal root cause of the reported confusion — a user
(or a future engineer) reading either name in isolation has no reliable way
to tell which of the two systems is being referenced.

## Investigation and design decision

Before making any change, both backend systems were read in full:

- `routes/tradingCoach.ts` / `lib/tradingCoach.ts` (mounted at `/trading/coach/...`)
- `routes/aiTradingCoach.ts` / `lib/tradingCoachUnified.ts` (mounted at `/trading-coach/...`)

**Finding:** these are not accidental duplicates safe to merge. Their `ask`
endpoints reuse the same `narrateTradeFreeform`/`narrateTradeFreeformStream`
functions from `coachLLM.ts`, but with genuinely different grounding context —
the v1.3.0 unified system's `buildUnifiedCoachContext()` is a **strict
superset** of the Sprint-47 system's own `buildTradeCoachContext()`, adding
Scanner, Trade Execution Center, and options-income Portfolio/Dashboard
visibility the older context lacks, and persisting both turns to a database
table the older system never touches. Because the sprint's own explicit
instructions forbid "behavioural changes to existing AI responses," **neither
backend route, function, or response shape was touched.** Merging, redirecting,
or removing either would have been a genuine behavioral change (a caller of
one endpoint would silently start receiving a materially different context),
not a pure naming fix — so this was deliberately left as a disclosed,
in-scope decision rather than attempted.

**Resolution chosen:** rename the user-facing v1.3.0 system from "AI Trading
Coach" to **"AI Trading Assistant"**, leaving "Trading AI Coach" (Phase 29)
completely unchanged. This follows an existing convention already present in
this codebase's own navigation (`lib/nav-items.ts`): "AI Assistant" (the
original Options Engine's free-form chat page) already sits beside "AI
Trading Coach" as a sibling nav item — "Assistant" for free-form chat,
"Coach" for deterministic, topic-scoped explanation. Applying that same
convention to the confusing pair resolves the collision immediately, using a
pattern the platform already established elsewhere.

**No route or URL was changed.** `/ai-trading-coach` and `/trading-ai-coach`
are both still live, completely unchanged. Only user-visible labels, titles,
`aria-label`s, and placeholder text were renamed. Because no URL moved, **no
redirect or alias mechanism was needed or added** — every existing bookmark,
deep link, or hardcoded href to either path continues to resolve exactly as
it did before this sprint.

## Routes updated

**None.** Every backend route, path, request/response shape, and narration

comment-only header note (see below) documenting its relationship to the
sibling `routes/aiTradingCoach.ts` router — zero logic change.

## Components consolidated

`components/coach/TradingCoachDrawer.tsx` — its own exported React component
(`TradingCoachDrawer`) was confirmed, via precise grep, to be **dead code**:
never rendered anywhere in the application. `pages/TradingAICoach.tsx` (the
Phase 29 "Trading AI Coach" page) imported only two constants from this file
(`TRADING_COACH_TYPES`, `TRADING_COACH_TYPE_LABELS`) and rendered its own,
separate inline Card-based Evidence Explorer UI instead. The component's only
real consumer was its own dedicated `TradingCoachDrawer.test.tsx` (12 tests
exercising dead code).

Resolution:
- New `lib/trading-coach-types.ts` holds the two still-needed constants,
  unchanged, with a comment explaining the extraction.
- `TradingCoachDrawer.tsx` (291 lines) and `TradingCoachDrawer.test.tsx`
  (168 lines) were deleted in full.
- `pages/TradingAICoach.tsx`'s one import line was updated to the new path.
- Confirmed via grep that no other file in the codebase referenced
  `TradingCoachDrawer` after the change.

`components/coach/CoachDrawer.tsx` (the generic, Investing-Engine-side shared
drawer used by 8 other pages) is unrelated to this collision and was not
touched.

## Redirects / aliases introduced

**None.** No URL changed, so no redirect or alias mechanism was required.
Both `/ai-trading-coach` and `/trading-ai-coach` remain live, unchanged
routes; every existing bookmark or hardcoded link to either continues to
resolve identically to before this sprint.

## Compatibility considerations

- Zero routes removed or renamed — full backward compatibility by
  construction, not by redirect.
- Zero backend request/response shape changes — every generated API client
  type is untouched.
- The one behavioral non-change worth restating: the two backend `ask`
  endpoints (`/trading/coach/ask[/stream]` and `/trading-coach/ask[/stream]`)
  remain deliberately separate, each with its own grounding context, exactly
  as before this sprint.

## Validation results

All four required validation phases were run for real, in order, against a
local Postgres 16 instance (the sandbox's shipped `dkos_dev` database,
synced to the current Drizzle schema via `drizzle-kit push` — a pure local
test-environment step, not a production migration; **no manual migration
file was created or modified**, and CLAUDE.md rule 7's nullable → backfill →
enforce discipline was never invoked since no schema shape changed).

1. **TypeScript typecheck** (`pnpm run typecheck`) — clean across all 5
   workspace packages (`api-server`, `ravish-trading`, `e2e`,
   `mockup-sandbox`, `scripts`).
2. **Backend test suite** (`pnpm --filter @workspace/api-server run test`,
   serial/`--no-file-parallelism`) — **244/244 test files, 2867/2867 tests
   passed.** One environment-only wrinkle, fully diagnosed and resolved, not
   a code issue: this sandbox's cold `app.js` import (many dozens of routes)
   exceeds Vitest's default 10-second hook timeout under this environment's
   available CPU/disk throughput; re-run with `--hookTimeout=30000
   --testTimeout=30000` (and `BETTER_AUTH_SECRET` generated for the session,
   since it has no persisted value) passed every file with zero failures.
   Classified **⚠️ Environment / infrastructure** — confirmed unrelated to
   Sprint 1 by the fact that Sprint 1 touched zero backend route files
   besides one comment-only edit to `routes/tradingCoach.ts`.
3. **Frontend test suite** (`pnpm --filter @workspace/ravish-trading run
   test`) — **111/111 test files, 1282/1282 tests passed**, including every
   assertion updated to match the renamed "AI Trading Assistant" text
   (`AppLayout.test.tsx`'s `toHaveAccessibleName("Open AI Trading
   Assistant")`, `TradingCoachPresentational.test.tsx`'s `getByText("AI
   Trading Assistant")`).
4. **Production build** (`PORT=5000 BASE_PATH=/ pnpm run build`) — all
   packages built successfully. The pre-existing "chunks larger than 500 kB"
   Rollup warning (largest chunk `index-*.js` at ~576 kB) is unrelated to
   this sprint — it reflects the platform's overall page count grown across
   many prior sprints, not anything Sprint 1 added or removed; Sprint 1's
   own dead-code removal (459 deleted lines) is a net negative contribution
   to bundle size, not a cause of the warning.

**Failure classification summary:** zero ❌ New Sprint 1 regressions. One ⚠️
Environment/infrastructure item (hook-timeout tuning, resolved for this
validation run, not a code change). Zero ✅ Previously documented failures
