# v1.4.0 — Learning Centre Sprint L2D: Platform Operations Academy

**Branch:** `v1.4.0-learning-centre-l2d` (off `main`, post-Sprint-L2C merge
commit `17fa212`)
**Scope, as explicitly approved:** document the remaining operational
modules using the real application implementation — Watchlists & Market
Scanner, Alerts & Notifications, Research Terminal (calendar/AI
summaries/daily preparation), and Settings & Personalisation. Do NOT
merge into `main`. Open a Pull Request and wait for approval.

---

## 1. Objective

Continue the Platform Academy with 4 further Learning Centre lessons
covering platform operations rather than a single engine's own workflow.
Every lesson follows the same rich-content shape established in
Sprints L1/L2A/L2B/L2C. Per the explicit quality requirement — "if a
requested feature is not implemented, explicitly state this and explain
the current implementation instead" — this sprint required more real-code
investigation than any prior one, since several requested teaching points
(a news feed, a custom "create alert" UI, a theme toggle, AI-preference
settings, backup/restore) turned out not to exist, and 2 of the 4
requested modules turned out to substantially overlap with content
already shipped in Sprint L2A.

## 2. Real Platform Analysis (performed before authoring any content)

Four parallel, read-only investigation passes were run against the real
source tree before any content was written, each producing a precise,
file-and-line-referenced inventory. Key findings:

- **Watchlists & Market Scanner** — genuinely **two separate watchlist
  systems** exist: a flat, single, unnamed Value Watchlist (one list per
  user, a tab inside `StockResearch.tsx`, with real opt-in price/margin-
  of-safety target checking via `lib/watchlistTargets.ts`), and the
  **Institutional Watchlists & Opportunity Dashboard**
  (`pages/WatchlistsEngine.tsx`, `/watchlists-engine`) — genuinely
  multiple, named, independently-manageable watchlists. The options-
  income **Market Scanner** (`pages/Scanner.tsx`, `/scanner`) exposes
  exactly one filter (Strategy) and has no save-scan feature at all — the
  **only** page in the platform with a real "save this scan" feature is
  **Opportunity Discovery** (`/opportunity-discovery`, Saved Screens).
  `pages/StockScanner.tsx` (`/stock-analyst/scanner`) is a related but
  distinct client-side-filtered screen.
- **Alerts & Notifications** — confirmed **three** real subsystems, not
  two: the Notification Center (`lib/notifications.ts`, the header bell)
  and the Monitoring & Alerts Engine (`lib/monitoringEngine.ts`,
  `/monitoring-dashboard`) share the same underlying `platform_notifications`
  table and are functionally merged into one automatic 5-minute pipeline;
  the genuinely separate **Compliance Policy Engine**
  (`/monitoring-compliance-engine`) is the **only** place a user can
  define their own numeric limit — called a "Policy," never an "alert."
  Confirmed **no** create/edit-alert UI exists anywhere, and **no**
  AI-generated alert content exists anywhere — all 14 alert types are
  fixed, deterministic, template-based checks. The pre-existing
  `investing-monitoring` Learning Centre topic was found to contain two
  factual inaccuracies: it stated severity as "low/medium/high" (the real
  vocabulary, confirmed against both source code and the existing
  `alert-severity` glossary entry, is info/warning/critical) and implied
  user-configurable triggers exist (they don't).
- **Research Terminal** — confirmed the existing `investing-research-terminal`
  topic's own 9-tab list (Overview/Statements/Decision Engine/Investment
  Committee/Investment Memo/Portfolio Impact/Monitoring/Evidence/Notes) is
  accurate and complete — no News tab, no Economic Calendar tab. Confirmed
  **no news feed exists anywhere in this codebase**, not even in simulated
  form — a single unused string literal in a type union is the closest
  thing. Confirmed a real, deterministic, **SIMULATED** Economic Calendar
  does exist, but as a wholly separate page (`pages/Events.tsx`, `/events`,
  its own heading literally reads "Economic Calendar"). Confirmed real
  AI-narration entry points exist (AI Research Thesis on `/stock-analyst`,
  Ask-the-AI-Investment-Analyst inherited inside the Terminal's own
  Overview tab, "Narrate My Day" on the Cross-Engine Daily Report
  `/daily-report`, Market Briefing narration on `/portfolio-ai`) — but the
  Terminal's own Overview tab deliberately replaces the auto-generated AI
  Research Thesis with a static disclaimer.
- **Settings & Personalisation** — read `Settings.tsx` in full (760
  lines): exactly 7 cards (Execution Engine, Market Data, Broker
  Connection, Fundamentals Data, Live Provider Status, Event Risk Filter,
  Alerts & Notifications), no theme card, no AI-preferences card.
  Confirmed **no light/dark theme toggle exists anywhere** — the app is
  permanently dark-themed at the CSS level. Confirmed 3 genuinely separate
  real personalisation mechanisms: sidebar collapse/pin/compact prefs
  (localStorage, global), Research Terminal's own page-scoped Saved
  Layouts (localStorage, that page only), and the Home page's real,
  **server-side, multi-workspace** Workspace System
  (`lib/dashboardWorkspaces.ts` + `pages/Home.tsx`) — the platform's true
  "dashboard customisation" feature. Confirmed the AI Coach's Beginner/
  Advanced depth toggle is **not** a saved preference — pure in-memory
  state resetting on every page reload. Confirmed **no backup-and-restore
  or general data export/import feature exists anywhere** — the only real
  export is a narrow CSV download of currently-open trade positions only.

## 3. Design decisions made during implementation

- **Upgrade-in-place vs. new topic, per the L2A/L2C-established
  heuristic.** `investing-monitoring` (title "Monitoring & Alerts")
  already matched the requested Alerts & Notifications module directly —
  it was **upgraded in place**, correcting its 2 factual inaccuracies
  (severity vocabulary, the false implication of user-configurable
  triggers) as part of the honest-content requirement. The other 3
  modules required genuinely **new** topics:
  - `options-scanner-watchlists` — since `investing-opportunity-discovery`
    (an existing topic) already covers Opportunity Discovery's own
    screen→rank→bucket mechanic; this new topic deliberately does not
    re-explain that mechanic, instead covering the Market Scanner, both
    watchlist systems, and the Saved Screens feature's actual home.
  - `investing-research-workflow` — since `investing-research-terminal`
    already comprehensively covers the Terminal's own 9 tabs; this new
    topic explicitly opens by stating it does not re-explain them, and
    covers only what's genuinely outside the Terminal (the Economic
    Calendar, the real AI-narration entry points, and a genuine daily-
    preparation workflow) plus the one explicit honest disclosure (no
    news feed exists).
  - `platform-settings-personalisation` — no existing topic covered
    Settings at all; this is genuinely new territory.
- **Honest disclosure over invented functionality, per the explicit
  "if a requested feature is not implemented, explicitly state this"
  requirement.** Five requested teaching points do not correspond to real
  features and are each explicitly, plainly disclosed rather than
  invented or silently omitted: a news feed (doesn't exist anywhere,
  not even simulated); a "create/edit a custom alert" UI (doesn't exist —
  reframed to the real Compliance Policy Engine, which is a genuinely
  different, separately-named feature); a light/dark theme toggle
  (doesn't exist — the app is permanently dark-themed); a persisted
  AI-preference setting (doesn't exist — the Beginner/Advanced toggle is
  per-message, non-persisted); and backup/restore (doesn't exist — only a
  narrow, positions-only CSV export exists, explicitly distinguished from
  a real backup feature).
- **Placement, per the intra-path `nextStepKeys` constraint first
  discovered in Sprint L2A.** `options-scanner-watchlists` was appended
  as a new 4th topic to `options-income-engine` (after
  `trade-execution-order-management`). `investing-research-workflow` was
  inserted into `institutional-investing` immediately after
  `investing-research-terminal`, with both topics' `nextStepKeys`
  rewired so the existing chain (`investing-research-terminal` →
  `investing-investment-committee`) still resolves, just through the new
  topic. `investing-monitoring` kept its existing position (upgraded in
  place, key unchanged). `platform-settings-personalisation` was inserted
  into `platform-basics` immediately after `ai-coach-overview` (a
  platform-mechanics topic, matching the precedent set by
  `institutional-dashboard-overview`/`ai-coach-overview` in L2A/L2B),
  with the existing chain (`ai-coach-overview` → `learning-centre-overview`)
  rewired through it.
- **Glossary reuse discipline.** All glossary keys referenced across all
  4 lessons (`screener`, `watchlist-and-opportunity-triggers`,
  `opportunity-buckets`, `opportunity-ranking`, `monitoring-alert`,
  `alert-severity`, `portfolio-drift-alert`, `research-terminal`,
  `event-risk`, `command-palette`, `simulated-vs-live`) were confirmed to
  already exist in `lib/glossary.ts` before use — no new glossary terms
  were added this sprint.
