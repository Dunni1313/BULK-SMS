## 1. Objective

The Learning Centre must teach users how to use every part of the
platform as an interactive institutional training system, not a static
help page. Each of the 4 module guides below follows an identical,
required 9-section shape: Module Overview, Institutional Thinking, Screen
Walkthrough, Guided Workflow, Worked Examples (Good/Average/Poor), Common
Mistakes, Risk Considerations, AI Coach prompts, Next Lesson — grounded
entirely in the REAL, current implementation of each module, verified by
direct source inspection before a single word of lesson content was
written (never invented, never describing a feature that doesn't exist).

## 3. Design decisions made during implementation (not separately asked, applied by direct precedent)

- **Where each module guide lives.** `LessonRenderer.tsx`'s own
  `nextStepKeys` resolution is intra-path only (`siblingTopics.find(...)`
  against the SAME `LearningPath`'s own topics array) — a cross-path
  "Next Lesson" link silently wouldn't resolve. Rather than modify that
  shared component (out of scope, and the user explicitly deferred the
  `learningPaths.ts` refactor), each module guide was placed in its own
  most natural existing/new path so its own intra-path "Next Lesson" chain
  genuinely works, and cross-module navigation between the 4 guides is
  wired via `relatedModuleHrefs` (which already supports linking to any
  route, including a `/learn/paths/:pathKey` lesson page, not just a tool
  page) plus explicit body-text guidance.
  - **Command Centre** — upgraded the existing `command-centre-overview`
    topic in place (`platform-basics` path), which already existed as a
    brief Sprint L1 stub. Its own `nextStepKeys` chain
    (`→ learning-centre-overview`) is unchanged.
  - **Institutional Investing Engine** — upgraded the existing
    `investing-research-terminal` topic in place
    (`institutional-investing` path), since the Research Terminal already
    *is* that engine's own unified, end-to-end experience. Its
    `nextStepKeys` now points to `investing-investment-committee` (the
    next topic already in that path), so its "Next Lesson" link is
    real and clickable.
  - **Institutional Trading Engine** — added a brand-new topic,
    `trading-engine-overview`, as the first entry in the existing
    `trading-engine` path (ahead of the pre-existing
    `trading-market-structure` topic, which is untouched). Its
    `nextStepKeys` points to `trading-market-structure`.
  - **Options Income Engine** — added a brand-new, twelfth `LearningPath`,
    `options-income-engine` (glossaryCategory `"strategies"`), with one
    topic, `options-income-engine-overview`. This fills a genuine,
    pre-existing gap: `institutional-investing` and `trading-engine`
    already played the "engine tour" role for Engines 1 and 2
    respectively (added in Phases 21 and 29), but Engine 3 — the
    platform's original, mature foundation — had no equivalent single
    "how professional users work this whole engine" path; every one of
    its pre-existing paths (`foundations`/`greeks`/`volatility`/
    `strategies`/`portfolio`/`performance`/`institutional`) teaches
    options CONCEPT vocabulary, not a tour of the Trade Execution
    Center's own screens. Adding one new `LearningPath` object is
    ordinary content addition, not the file-split refactor the project
    owner deferred.
- **`workedExamples` (plural) schema extension.** The pre-existing
  `LearningTopic.workedExample` field is singular; the approved brief
  required 3 distinct, labeled examples per lesson (Good/Average/Poor
  Opportunity). Added a new, optional `workedExamples?:
  LearningTopicWorkedExample[]` field (the older singular field is
  completely untouched and still supported — `platform-basics-navigation`,
  the one pre-existing topic using it, is unmodified) and an optional
  `label?: string` on `LearningTopicWorkedExample` for the tier badge.
  Threaded through `lib/learningPaths.ts` (backend interface),
  `openapi.yaml` (`LearningTopic.workedExamples`,
  `LearningTopicWorkedExample.label`), regenerated `api-zod`/
  `api-client-react` via the standard `pnpm --filter @workspace/api-spec
  run codegen`, and `LessonRenderer.tsx` (a new "Worked Examples" section
  rendering each labeled example, alongside the pre-existing singular
  "Worked Example" section, unchanged).
