# v1.4.0 — Learning Centre Sprint L2B: Cross-Engine & Portfolio Hubs

**Branch:** `v1.4.0-learning-centre-l2b` (off `main`, post-Sprint-L2A
merge commit `3441a08`)
**Scope, as explicitly approved:** build 4 further comprehensive Learning
Centre guides — Institutional Dashboard (Cross-Engine Command Centre),
Portfolio AI / Portfolio Dashboard, Institutional Mentor, AI Coach — plus a
new, lightweight, lesson-level Knowledge Check reusing the existing Learning
Centre architecture (no new quiz engine). Do NOT merge into `main`. Open a
Pull Request and wait for approval.

---

## 1. Objective

Extend the Learning Centre's Interactive Module Guides (established in
Sprint L2A) to 4 further modules the project owner selected as "Cross-Engine
& Portfolio Hubs": Institutional Dashboard, Portfolio AI, Institutional
Mentor, and AI Coach. Each lesson follows the identical 13-part shape every
prior rich lesson uses (Overview/Purpose, Screen Walkthrough with every
panel explained, Step-by-step workflows, Worked Examples, Common Mistakes,
Best Practices/Professional Tips, AI Coach prompts, Related Modules,
Glossary links, Bookmark support, Progress tracking) plus one new part this
sprint adds to the shared template itself: a lesson-level **Knowledge
Check** — 5-6 multiple-choice questions with instant feedback, explanations,
and completion tracking integrated into the existing progress system.

## 3. Design decisions made during implementation (per the project owner's own explicit selections)

- **Lesson placement, per the intra-path `nextStepKeys` constraint
  first discovered in Sprint L2A.** `LessonRenderer.tsx`'s "Next Lesson"
  resolution is still intra-path only, so each new lesson was placed in
  the path where its own chain genuinely resolves:
  - **Institutional Dashboard** and **AI Coach** — 2 new topics inserted
    into the existing `platform-basics` path (between
    `command-centre-overview` and `learning-centre-overview`), since both
    are platform-mechanics lessons, not an investing/trading concept.
    The chain is now `platform-basics-navigation → command-centre-overview
    → institutional-dashboard-overview → ai-coach-overview →
    learning-centre-overview`.
  - **Portfolio AI** — a new second topic (`portfolio-ai-overview`)
    appended to the `options-income-engine` path (Sprint L2A's own new
    path), immediately after `options-income-engine-overview`, since
    Portfolio AI is that same engine's own cockpit/monitoring surface.
  - **Institutional Mentor** — a new final topic
    (`investing-institutional-mentor`) appended to the
    `institutional-investing` path, after `investing-opportunity-discovery`.
  - `platform-basics` therefore grows from 3 to 5 topics; every other path
    grows by exactly 1 topic — a disclosed, intentional expansion, not a
    regression of any prior sprint's own content.
- **Knowledge Check: reuse, not a new quiz engine, per explicit
  instruction.** The pre-existing `DeltaMasterclass.tsx` page had its own
  private comprehension-check card (prompt/options/correctIndex/
  explanation, instant feedback, "Try again"). That component was
  extracted, unmodified in its own rendering logic, into a new shared
  `components/learn/QuizCard.tsx` — typed structurally via a new local
  `QuizCardQuestion` interface rather than importing either domain's own
  generated type (matching the established "never cross-import a type
  between `coach.ts`'s `LearnContent` domain and `learningPaths.ts`'s
  `LearningTopic` domain" precedent). `DeltaMasterclass.tsx` now imports
  and renders the shared component with zero behavior change of its own.
  A new `LearningTopicQuizQuestion` interface (structurally identical to
  `QuizCardQuestion` and to the pre-existing `LearnQuizQuestion`, but
  declared independently, per that same precedent) backs a new optional
  `LearningTopic.knowledgeCheck?: LearningTopicQuizQuestion[]` field.
- **Completion tracking: a new self-contained component, following
  `BookmarkButton.tsx`'s established pattern, not `LessonRenderer`'s own
  prop-driven Mark Complete.** A new `components/learn/KnowledgeCheck.tsx`
  owns its own `useGetLearningProgress()`/`useRecordLearningItemCompleted()`
  calls internally (rather than being fed `completed`/`onMarkComplete`
  props from the parent page, the way the lesson's own overall "Mark
  Complete" button works) — the same "self-contained, progress-aware
  component" shape `BookmarkButton.tsx` already established for bookmarks.
  A new `"knowledge-check"` value was added to the existing
  `LearningItemType` union (`lib/learningProgress.ts`) — the DB's own
  `learning_progress.item_type` column is, and always was, a plain,
  unconstrained `text()` column, so this needed **zero database
  migration**, mirroring Phase 21's own precedent for adding `"coach"`.
  Completion is deliberately **ungraded and ungated**: once every question
  in a lesson's Knowledge Check has been answered at least once (right or
  wrong — a "Try again" re-answer never un-completes it), completion fires
  exactly once via `recordCompleted({ itemType: "knowledge-check", itemKey:
  <topic key> })`. A running "X of N answered — Y correct on first try"
  line is shown for the learner's own benefit only; it never blocks or
  delays completion, consistent with `QuizCard`'s own "client-side,
  ungraded comprehension check" design.
- **Backend rollup: `completedKnowledgeCheckKeys`, mirroring
  `completedCoachKeys` exactly.** `getLearningProgress()`
  (`lib/learningProgress.ts`) gained a new `completedKnowledgeCheckKeys:
  string[]` field, computed identically to the existing
  `completedCoachKeys` (`progressRows.filter(r => r.itemType ===
  "knowledge-check" && r.completedAt !== null).map(r => r.itemKey)`) — no
  new query, no new aggregation shape.

## 6. Database / API changes

- **No database migration.** `learning_progress.item_type` was always a
  plain, unconstrained `text()` column — the new `"knowledge-check"` value
  requires no schema change, mirroring Phase 21's own `"coach"` precedent.
- **OpenAPI**: `LearningTopic` gained an optional `knowledgeCheck` array
  field (`$ref` to a new `LearningTopicQuizQuestion` schema, shape
  `{prompt, options, correctIndex, explanation}`); every existing
  `itemType` enum (`RecordLearningItemViewed`/`RecordLearningItemCompleted`/
  `LearningBookmarkEntry`/`RecordLearningBookmark`) gained the new
  `knowledge-check` value; `LearningProgressSummary` gained a required
  `completedKnowledgeCheckKeys: string[]` field. All purely additive.
  `api-zod`/`api-client-react` regenerated cleanly via the standard
  codegen command, no collisions.
