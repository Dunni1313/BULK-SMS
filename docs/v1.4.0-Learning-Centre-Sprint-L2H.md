## 1. Platform inspection summary (the implementation map)

Three parallel, read-only investigation passes were run before any content
was written — covering (1) the core Portfolio dashboard/Greeks
computation, (2) portfolio risk-management tools (stress test,
concentration, event risk, and hard-enforced vs. advisory risk gates), and
(3) AI Coach/Portfolio Analyst/Institutional Mentor capabilities plus
pre-existing Learning Centre content, to avoid duplication. Two further
targeted, direct source checks closed remaining gaps (realized P/L, and
`Adjustments.tsx`'s real panels). Key findings, each independently
confirmed by direct source inspection:

- **The platform's "portfolio" surface is genuinely spread across several
  distinct real screens, not one unified dashboard.** `/portfolio` is
  actually titled "Portfolio Greeks" and shows only positions, Greeks, and
  per-position unrealized P/L — it does **not** show portfolio value,
  buying power, cash, or realized P/L at all. Those figures live
  elsewhere: portfolio value/buying power/day P&L/total P&L on the
  Account Snapshot (`/portfolio-ai`), and realized performance as the
  Total P&L KPI on Performance Analytics (`/trade-performance`), computed
  only from actually-closed trades.
- **Cash Balance is a real, computed backend field
  (`routes/portfolio.ts`'s `/summary` endpoint) that is honestly disclosed
  as not currently rendered on any screen** — confirmed by grepping both
  `Portfolio.tsx` and `PortfolioAI.tsx` for any "Cash" label; neither
  renders it, even though `PortfolioAI.tsx` already calls the exact
  endpoint that returns it.
- **The "Beta-Weighted Delta" label mismatch, first found in a prior
  sprint, is confirmed still present**: portfolio-level Greeks are a plain,
  un-weighted sum of every open position's own Black-Scholes deltas
  (`routes/portfolio.ts:97-105`) — no beta coefficient anywhere in the
  codebase, corroborated by `netBeta: null` appearing throughout
  `portfolioDashboard.ts`/`portfolioConcentration.ts`.
- **Concentration Score is a genuine Herfindahl-Hirschman Index**, a
  standard statistic, not a fabricated formula
  (`portfolioConcentration.ts`) — but "Correlation Clusters" are explicitly
  disclosed as categorical grouping (shared symbol/sector/strategy/
  expiration/directional bias), never a real statistical correlation
  coefficient; no price-return covariance matrix is computed anywhere.
  Sector classification is a small, static, hand-curated table, not live
  market data.
- **Maximum portfolio risk is genuinely, mechanically hard-enforced**:
  `settings.maxRiskPerTrade`/`maxPortfolioRisk` are checked by
  `execution.ts`'s `validatePreTrade()` before any order — manual,
  semi-auto, or full-auto — can be submitted; a breaching trade is rejected
  outright. This is a real, different mechanic from `positionSizing.ts`'s
  own `recommendedQuantity`, which is confirmed **purely advisory** by its
  own header comment — it never calls into the order-submission path and
  cannot block a trade.
- **Rolling and converting are genuinely implemented**, not purely
  conceptual: `adjustment.ts`'s real `AdjustmentAction` union includes
  `roll_threatened`/`roll_untested`/`convert` as detected, real
  recommendations shown in the Adjustments page's Attention Queue
  (Severity/POP/DTE columns) — with the one honest caveat, stated directly
  in that file's own comment, that structural changes like rolls and
  converts are "NEVER auto-run," always human-gated on the Trade Ticket.
- **The word "AI" means genuinely different things across three separate
  portfolio-review surfaces.** Only the Market Briefing and Report
  Comparison narrations (`/portfolio-ai`) are genuinely streamed LLM
  prose. Both the AI Portfolio Analyst (`/portfolio-analyst`) and the
  Institutional Mentor (`/institutional-mentor`) state directly, in their
  own header comments and frontend badges, that they are "not an LLM, not
  a chatbot, not predictive AI" — deterministic, template-and-threshold
  compositions of already-computed figures. No free-form question box
  exists on any of the three real portfolio-review pages.
- **No single dedicated "Daily Review" or "Weekly Review" feature exists**
  — confirmed both by direct inspection and by the pre-existing
  `trading-journal-review` lesson's own established honest framing ("Journal
  + AI Coach together, not a single dedicated feature"), which this
  sprint's content explicitly mirrors for the portfolio-account level too.

## 2. Design decisions made during implementation

- **3 new topics + 2 upgrades-in-place, all within the existing, still-all-
  plain `PORTFOLIO_PATH`** (mirroring Sprint L2G's precedent of building
  within an existing path rather than a new top-level one): `portfolio-
  overview` (new), `portfolio-concentration` (upgraded → Module 2 Portfolio
  Greeks), `portfolio-position-sizing` (upgraded → Module 3 Risk
  Management), `portfolio-managing-positions` (new), `portfolio-ai-review-
  workflow` (new). `portfolio-health`, `portfolio-buying-power`,
  `portfolio-diversification`, `portfolio-correlation`, `portfolio-stress-
  testing`, `portfolio-event-risk`, and all of `PERFORMANCE_PATH` were
  correctly left untouched — out of scope, and their content is
  cross-referenced (never duplicated) from the 5 new/upgraded lessons.
- **Module 2 ("Portfolio Greeks") deliberately does NOT duplicate the
  pre-existing, already-rich `greeks-portfolio-greeks` lesson**
  (`GREEKS_PATH`, shipped in Sprint L2F) — that lesson already covers the
  Greeks math/formulas and the Beta-Weighted-Delta mislabel in depth.
  `portfolio-concentration`'s upgraded content instead covers the
  genuinely distinct, additive angle of *using* net Greeks to reason about
  diversification/concentration, plus the one real Greeks chart (the
  Greeks Contribution bar chart on `/concentration-risk`), neither of
  which the existing lesson covers — explicitly cross-referencing it
  rather than re-deriving its math.
- **Module 5 ("AI Portfolio Review") is deliberately narrow and honest
  about what "AI" actually means at the portfolio level** — this was the
  single most important honesty decision this sprint made. Rather than
  describing Portfolio Analyst's or Institutional Mentor's deterministic
  scoring as "AI reasoning," or inventing a free-form chat-with-the-AI-
  about-your-portfolio capability that doesn't exist, the lesson draws the
  same line the platform's own source code already draws: genuine LLM
  narration (Market Briefing, Report Comparison) versus explicitly
  self-disclaimed deterministic composition (Portfolio Analyst,
  Institutional Mentor).
- **`portfolio-position-sizing`'s upgrade explicitly distinguishes
  hard-enforced risk caps from advisory-only sizing suggestions** — a
  genuine, load-bearing distinction confirmed by direct source inspection
  (`execution.ts`'s `validatePreTrade` vs. `positionSizing.ts`'s own header
  comment), not previously covered by the original plain stub.
- **New glossary terms**: `account-value`, `cash-balance`,
  `unrealized-pnl`, `realized-pnl`, `max-portfolio-risk` — all category
  `portfolio`. No existing glossary entries needed correction this sprint
  (unlike prior sprints, no factual mismatch was found in the pre-existing
  Portfolio/Performance category entries).
- **One genuinely new route added to `knownRoutes`**: `/portfolio-analyst`
  — confirmed as a real, already-registered `App.tsx` route (`App.tsx:178`)
  simply never previously referenced by any Learning Centre topic.
- **`nextStepKeys` chains kept within the `portfolio` path** throughout
  (`portfolio-overview` → `portfolio-concentration` → `portfolio-position-
  sizing` → `portfolio-managing-positions` → `portfolio-ai-review-
  workflow` → end), matching the established same-path discipline from
  prior sprints even though the test enforcing this is scoped only to
  `platform-basics`.
- **Worked-example count constraint, re-confirmed**: exactly 3 worked
  examples labeled `["Good Opportunity", "Average Opportunity", "Poor
  Opportunity"]` per module-guide topic — all 5 new/upgraded topics
  verified via script before running any test.
