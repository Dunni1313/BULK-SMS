# v1.4.0 — Learning Centre Sprint L1: Foundation

Branch `v1.4.0-learning-centre`. This is the **first implementation
sprint** of the Learning Centre, following the approved Architecture
Blueprint and Learning Content Master Plan (both delivered and frozen as
this sprint's own source of truth, prior to any code being written). Per
the sprint's own explicit scope, this ships only the **reusable
infrastructure** — the Learning Home Dashboard, navigation, search
integration, bookmarks, progress tracking, and the shared lesson
rendering template — plus exactly three foundation lessons. It does
**not** ship the remaining curriculum, guided tours, certifications,
quizzes, Example Mode, or the Trading/Platform Academies — those remain
scoped to later sprints (L2+).

## Objective

Build the platform foundation the Learning Content Master Plan's ~70
future lessons will all sit on top of, proving the template works via
three real, fully-populated lessons rather than a mock-up.

## Screens implemented

1. **Learning Home Dashboard** (`LearningCentre.tsx`, new "Explore" tab,
   now the page's default tab) — the Learning Home Dashboard the
   blueprint specified:
   - **Browse by Category** — 5 cards routing to each of the platform's
     major surfaces (Institutional Investing, Institutional Trading,
     Options Income & Paper Trading, Cross-Engine & Executive, Platform
     Basics), each linking to a real, already-existing page.
   - **Continue Learning** — surfaces the next uncompleted topic in
     whichever learning path the user has made the most progress in
     (derived from the existing `pathCompletion` data, zero new
     computation); honestly falls back to a "start with Platform Basics"
     prompt when nothing is in progress yet.
   - **Recently Viewed** — the 5 most recent items from the existing
     `recentHistory` feed, each resolved to a real link via the new
     `resolveItemHref()` helper, or rendered as plain, honest text when
     the owning page can't be resolved (never a fabricated link).
   - **Bookmarks** — the user's saved items (see below), same
     resolve-or-honestly-render-plain-text discipline.
   - The pre-existing Overview/Simulations/My Portfolio Explained/Progress
     tabs are completely unchanged in content and behaviour — only their
     position (no longer the default tab) moved.
2. **Rich lesson rendering** (`LearningPaths.tsx`'s existing path-detail
   view, now delegating to the new shared `LessonRenderer` for any topic
   that supplies rich content) — difficulty/time badges, a bookmark
   toggle, Overview, Why It Exists, Why It Matters, Institutional
   Thinking, Workflow, Screen Walkthrough, Metrics Explained, a Worked
   Example, Common Mistakes, Risk Considerations, Best Practices, related
   modules, related glossary terms, an "Ask the AI Coach" launcher, and a
   "Mark Complete" / "Next Lesson" footer. Topics with none of the new
   optional fields (all 68 pre-existing topics) continue to render via
   the exact pre-existing plain layout — nothing about their display
   changed.
3. **Search integration** — the existing Global Command Palette
   (`Cmd/Ctrl+K`) now also surfaces the user's bookmarked learning items,
   in a new "Bookmarks" group, resolved the same way as the dashboard's
   own Bookmarks section. No second search engine was built.

## Content implemented (the 3 approved foundation lessons)

A new 11th Learning Path, **Platform Basics** (`platform-basics`), with
exactly the 3 lessons specified:

1. **Platform Basics & Navigation** — the sidebar, its themed section
   groups, and the Command Palette; a guided tour is flagged as required
   (`guidedTourRequired: true`) for a future sprint to build, not built
   this sprint.
2. **Command Centre** — the executive landing page, linking out to
   `/command-center`.
3. **Learning Centre Overview** — the Learning Centre itself, linking to
   `/learn`.

Each lesson populates every one of the 13 new optional `LearningTopic`
fields, so this path doubles as the living template/reference
implementation for every future lesson author to copy.

## Components added

- `src/components/learn/LessonRenderer.tsx` — the shared lesson template
  (`LessonRenderer`) plus the `hasRichLessonContent()` predicate
  `LearningPaths.tsx` uses to decide which rendering path a topic takes.
- `src/components/learn/BookmarkButton.tsx` — the reusable bookmark
  toggle (lesson/glossary/path/strategy), reading state from the already-
  fetched `useGetLearningProgress()` query (no extra fetch of its own).
- `src/components/learn/AskCoachLauncher.tsx` — the reusable "Ask AI
  Coach" button/launcher.
- `src/lib/learning-item-href.ts` — `resolveItemHref()`, the single,
  shared resolver used by both the dashboard's Recently
  Viewed/Bookmarks sections and the Command Palette's Bookmarks group, so
  the two surfaces can never silently drift apart on how an item resolves
  to a real page.

## Components reused (per the sprint's explicit reuse mandate)

- **Cards / Tabs / Badges / Buttons / Skeletons** — every new screen is
  built entirely from the existing shadcn/ui primitives already used
  throughout `LearningCentre.tsx`/`LearningPaths.tsx`; no new design-
  system components were introduced.
- **Command Palette** (`CommandPalette.tsx`) — extended with one more
  lazily-fetched (`enabled: open`) data source and one more `CommandGroup`
  ("Bookmarks"), following the exact pattern already used for open
  positions, watchlist entries, and portfolios. No second search index,
  no new search algorithm — `cmdk`'s existing fuzzy filter covers it for
  free.
- **AI Coach infrastructure** — `AskCoachLauncher` is a thin wrapper over
  the already-global `TradingCoachProvider`/`TradingCoachPanel` (v1.3.1)
  via `useTradingCoach()`. No new chat UI, no new LLM endpoint, no new
  streaming logic was built — it opens the same panel every other page
  already uses.
- **Progress tracking model** — bookmarks extend the existing
  `learning_progress` table (one new nullable `bookmarked_at` column) and
  the existing `LearningProgressSummary` response shape (one new
  `bookmarks` array), reusing the exact upsert pattern
  `recordViewed`/`recordCompleted` already established. No new table, no
  new item-type enum value.
- **Glossary badges / related-term linking** — `LessonRenderer` reuses
  the exact `relatedGlossaryKeys` → `/learn/glossary/:key` badge pattern
  already established in `LearningPaths.tsx`/`ExplainButton.tsx`.

## Reuse discipline — what was deliberately NOT duplicated

Per the sprint's explicit instruction, nothing new was built where an
existing system already covered the need:

- No second search engine (Command Palette extended, not replaced).
- No new coach/chat component (existing `TradingCoachPanel` reused).
- No new progress/completion table or model (existing
  `learning_progress` extended additively).
- No new tooltip/drawer/dialog primitive.
- No new navigation shell (the existing sidebar/nav is untouched — the
  Learning Centre's own internal tabs handle in-page navigation).

## AI Coach

Only the reusable launcher was built (`AskCoachLauncher`), per the
sprint's explicit "do not create dozens of prompts yet" scope. A lesson
may supply `aiCoachPrompts` (shown as a hint, e.g. "Try asking: ...") but
nothing is auto-submitted — a real prefill-and-send flow is deferred
until a later sprint actually needs it for a broader curriculum.

## Search

The Learning Centre's own bookmarked content is now discoverable from
the existing Global Command Palette. Learning **paths** and **glossary
terms** were already searchable there before this sprint (pre-existing);
this sprint's own addition is specifically the Bookmarks group.

## Bookmarks

- Backend: `POST /learning-centre/progress/bookmark`
  (`{itemType, itemKey, bookmarked}`) upserts a `learning_progress` row's
  new `bookmarked_at` column (`setBookmarked()` in
  `lib/learningProgress.ts`); `GET /learning-centre/progress` now also
  returns a `bookmarks` array (newest-first).
- Frontend: `BookmarkButton` (used inside `LessonRenderer` today; the
  same component works for glossary/path/strategy items once those pages
  choose to add it in a later sprint).
- Migration: `lib/db/manual-migrations/038_learning_centre_bookmarks.sql`
  — one nullable `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, no backfill
  needed (brand-new column, defaults to `NULL` = not bookmarked).

## Progress / completion tracking

Unchanged from the pre-existing model (`recordViewed`/`recordCompleted`,
`pathCompletion`, `completedLessonKeys`) — this sprint only added the
bookmark dimension alongside it, using the identical per-row upsert
pattern.

## Accessibility summary

- `BookmarkButton` sets `aria-pressed` reflecting its toggled state, and
  is a real, keyboard-focusable `<button>` (native Enter/Space
  activation, no custom key handling needed).
- `AskCoachLauncher` opens the existing, already-accessible
  `TradingCoachPanel` (a Radix `Sheet`/`Dialog`-based component with its
  own established focus-trap and `aria-*` wiring, unchanged this sprint).
- Category cards, Continue Learning, Recently Viewed, and Bookmarks are
  all rendered as real `<a>`-backed `Link` components (via `wouter`) when
  a page can be resolved, so they are natively tab-reachable and
  screen-reader-navigable as links rather than as `<div onClick>`
  pseudo-links; when a link genuinely cannot be resolved, plain text is
  rendered instead of a non-functional link (never a link to nowhere).
- All new badges/sections in `LessonRenderer` use semantic elements
  (`<dl>`/`<dt>`/`<dd>` for Metrics Explained, `<ol>` for ordered
  Workflow/Worked-Example steps, `<ul>` for unordered lists) rather than
  generic `<div>`s, giving screen readers real list/definition semantics.
- Dark mode: every new component uses the existing Tailwind theme tokens
  (`text-muted-foreground`, `border-border`, `bg-secondary/20`, etc.) —
  no hardcoded colours — so it inherits dark/light theming automatically,
  the same as every other page in this codebase.
- Keyboard: the new Explore tab is reached via the existing `Tabs`/
  `TabsTrigger` Radix primitive, which already provides full keyboard
  arrow-key tab navigation; no custom keyboard handling was added or
  needed.

## Performance impact

- `CommandPalette.tsx`'s new `useGetLearningProgress()` call is gated
  `enabled: open`, matching every other data source already fetched in
  that component — it never fetches while the palette is closed.
- `BookmarkButton` reads from the page's already-fetched
  `useGetLearningProgress()` query rather than issuing its own request;
  multiple bookmark buttons on the same page (e.g. one per lesson) share
  one cached query.
- No new polling, no new background timers, no new heavy dependency was
  added — every new component is built from already-installed packages
  (`lucide-react` icons, existing shadcn/ui primitives, `@tanstack/react-
  query`).
- One new, small database column (`learning_progress.bookmarked_at`,
  nullable) — no new table, no new index required at this scale (the
  table is already indexed for per-user lookups by the pre-existing
  `learning_progress` schema).
- `LearningCentre.tsx`'s own built chunk grew from this sprint's Explore
  tab additions (`LearningCentre-B2fM-HbI.js`, 29.54 kB / 6.18 kB gzipped)
  — small in absolute terms and route-level code-split (per the v1.0.0
  Frontend Bundle Code-Splitting work), so it only loads when a user
  visits `/learn`. The production build's pre-existing "chunks larger
  than 500 kB" warning (the shared `index-*.js` entry chunk and the
  `recharts`-derived `generateCategoricalChart-*.js` chunk) is unrelated
  to this sprint — confirmed by inspecting the warning's own named chunks,
  neither of which contains any Learning Centre code, and both already
  being the largest chunks before this sprint's changes given how much
  the wider application has grown since the codebase's own last
  chunk-size measurement.
